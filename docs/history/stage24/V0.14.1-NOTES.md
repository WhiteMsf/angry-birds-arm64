# v0.14.1 — particleTable / runtime particles namespace reconstruction

v0.14 successfully crossed the ARMv7 `strength <= 0` branch:

- `WoodBlock6_5` reached negative strength;
- the object was inserted into `deadBlocks`;
- original `blockCollision()` advanced it to its final damage sprite;
- original `removeBlocks()` started processing the queued object.

The first failure occurred inside original `newParticles()` at PC 1 because
`particleTable` was nil.

## Static Lua proof

The stripped original bytecode shows:

```text
newParticles(type,...):
  0  GETGLOBAL particleTable
  1  GETTABLE  "particles"
  2  GETTABLE  [type]
  ...
  6  GETGLOBAL _G
  7  GETTABLE  "particles"
  8  GETTABLE  "addParticles"
```

Meanwhile original `particles.lua` builds the definition table containing
`smokeBuff`, `woodenBuff`, `rockBuff`, `lightBuff`, etc. and ends by assigning
that table to the name `particles`.

Those facts prove that the original runtime kept two particle namespaces:

```text
particleTable.particles   -> particle definitions from particles.lua
_G.particles              -> live/runtime particle surface with addParticles
```

Earlier bootstrap stages executed `particles.lua` directly in `_G`, collapsing
those namespaces into one table.

## v0.14.1 bridge

After executing the original six script chunks:

1. the table produced by `particles.lua` is preserved as
   `particleTable.particles`;
2. `_G.particles` becomes a clean runtime table;
3. `particles.addParticles` is exposed through the runtime table's metatable so
   `pairs(particles)` does not iterate over the method;
4. the actual visual particle spawning method is a headless no-op boundary,
   because rendering/particle simulation is outside Stage 13.

No collision, damage, score, deadBlocks, removeBlocks, removeObject, Box2D,
timing, or Level1 logic was changed.
