# v0.14.2 — particle runtime surface must be attached after level loading

v0.14.1 correctly reconstructed the definitions side:

```text
particleTable.particles -> definitions from particles.lua
```

but Stage 13 still failed in original `newParticles()` at PC 17:

```text
attempt to call field 'addParticles' (a nil value)
```

## Why

Exact stripped bytecode shows that the original game recreates the runtime
particle table itself.

`initialize()`:

```text
PC 233 NEWTABLE
PC 234 SETGLOBAL "particles"
```

`loadLevelInternal()`:

```text
PC 171 NEWTABLE
PC 172 SETGLOBAL "particles"
```

So the v0.14.1 runtime metatable was installed too early and was discarded by
the original loader.

## v0.14.2

After original `loadLevelInternal()` returns, v0.14.2 attaches the headless
native `addParticles` method to that newly-created `_G.particles` table through
its metatable.

It also verifies immediately that the exact original lookup

```text
_G.particles.addParticles
```

resolves to a function.

The method remains outside the table's own keys, preserving clean runtime
iteration.

No collision, damage, scoring, deadBlocks, removeBlocks, removeObject,
Box2D, timing, or Level1 logic changed.
