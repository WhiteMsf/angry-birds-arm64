# v0.15.2 — hold the bird probe across two native fixed steps

v0.15.1 proved that the active RedBird body is dynamic (`bodyType=2`) and that
the injected transform/velocity really reaches Box2D:

```text
requestedStart == actualStart
requestedVel   == actualVel
after Step: bird moved normally
```

Yet `BeginContact` did not fire in that same Step.

## Why this is consistent with Box2D 2.1.x

The 2.1-era world step can discover new broadphase pairs near the end of a
Step. The new contact object is then evaluated by the contact manager on the
following Step, which is when BeginContact can be emitted.

Our headless game loop calls original Lua `update()` between those 30 Hz fixed
steps. Because RedBird_4 has not actually been launched through the original
sling state machine, that Lua path moves it back toward the sling before the
next fixed Step. So the newly-created contact candidate never survives long
enough to become a touching contact callback.

## v0.15.2 microprobe

The same intentional overlap is now re-applied on two consecutive native
physics steps:

```text
frame 67 fixed Step: create broadphase/contact candidate
frame 69 fixed Step: keep overlap so ContactManager can evaluate it
```

The probe also logs:

- `world.GetContactCount()` before/after each held Step;
- cumulative BeginContact callback count;
- actual bird position/velocity.

No bird damage, score, birdCollision callback, or sling gameplay semantics are
implemented or guessed.
