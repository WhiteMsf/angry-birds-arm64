# v0.15.3 — inspect the raw Box2D contact object

v0.15.2 produced the most useful clue so far:

```text
frame 67 before Step: worldContacts=20
frame 67 after Step:  worldContacts=21
BeginContact callbacks: still 2
```

The same 21st contact persisted into frame 69, but still never became a
touching contact callback.

That proves the broadphase created a real contact object. The remaining
question is why that contact's narrow-phase state stays non-touching.

## One geometry mistake removed

The earlier probe assumed WoodBlock2_6 was effectively axis-aligned when
choosing the 1.60 center offset. But its Level1 body may be rotated, changing
the projected half-extent along X.

v0.15.3 removes that assumption entirely: for this diagnostic only,
RedBird_4 is placed at the exact current center of WoodBlock2_6 before the
held native fixed steps.

## New raw-contact dump

Before and after fixed steps 67 and 69, Stage 14 now iterates
`b2World::GetContactList()` and prints every contact involving RedBird_4 or
WoodBlock2_6:

- fixture/body pair names;
- `IsTouching()`;
- `IsEnabled()`;
- sensor flags;
- manifold point count;
- body types;
- category/mask/group filter data.

It also logs WoodBlock2_6's current body angle.

This should answer in one run whether the 21st contact is actually the
RedBird/target pair and, if so, whether the blocker is geometry,
touching/manifold state, sensor state, or filtering.

No birdCollision damage/scoring semantics are implemented.
