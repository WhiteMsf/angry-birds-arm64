# v0.18.3 — restore initCameras slider state

v0.18.2 got past the headless pause-button guard and reached the original
slingshot selection/drag path.

It then failed at stripped `updateGame` PC 2020:

```text
attempt to perform arithmetic on global 'cameraAnimationSlider' (a nil value)
```

The exact original bytecode is:

```text
2018 SETGLOBAL sweepSpeed = 0
2019 GETGLOBAL cameraAnimationSlider
2020 SUB       cameraAnimationSlider - dragDelta
2021 SETGLOBAL cameraAnimationSlider
2022 GETGLOBAL doItAllCamera
2023 SETGLOBAL cameraFunction
```

Static reconstruction of original `initCameras()` shows its final camera
initialization:

```text
375 LOADK      1.0
376 SETGLOBAL  cameraAnimationSlider
377 LOADK      1.0
378 SETGLOBAL  cameraAnimationSliderTarget
379 GETGLOBAL  defaultCamera
380 CALL
```

The headless bootstrap reconstructs the camera profiles but deliberately
does not execute the full `initCameras()` renderer/UI setup, so those two
otherwise-normal gameplay globals were absent.

## Fix

Supply the exact original post-`initCameras()` state:

```lua
cameraAnimationSlider = 1
cameraAnimationSliderTarget = 1
```

No slingshot input timing, cursor pull, original Lua drag/release logic,
impulse math, Box2D behavior, or Stage 17 verifier changed.
