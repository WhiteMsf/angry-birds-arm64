# v0.18.4 — isolate the camera subsystem from the slingshot milestone

v0.18.3 got substantially farther than the previous runs.

The original `updateGame()` accepted the Stage 17 press/hold input and reached
the drag path. During that path it executed:

```text
cameraAnimationSlider = cameraAnimationSlider - ...
cameraFunction = doItAllCamera
```

The slider globals were restored correctly, so execution continued until the
end-of-frame camera call. It then entered original `getTempBirdCamera()` and
failed at PC 13 because the rest of the full `initCameras()` state is absent.

That is an orthogonal subsystem.

## Why this is now a no-op boundary

Stage 17 is proving:

```text
platform LBUTTON/cursor input
  -> original updateGame selection
  -> original rubber-band drag
  -> original release math
  -> reconstructed native applyImpulse
  -> Box2D flight
```

The camera does not compute sling force or mutate the selected bird's launch
state. `doItAllCamera()` only follows/zooms the view and depends on the
renderer/viewport setup intentionally skipped by the headless bootstrap.

Rather than fabricate camera scalars (`currentZoomedScale`,
`minWorldScale`, `groundLimit`, `leftLimit`, etc.) one crash at a time,
v0.18.4 places the existing headless boundary at the subsystem entry:

```cpp
setfn(L, "doItAllCamera", l_noop);
```

The original `updateGame()` still assigns `cameraFunction = doItAllCamera`
exactly as before; the resulting function simply performs no rendering/camera
work.

## What did NOT change

No changes to:
- birdReady/currentBirdName timing;
- LBUTTON press/hold/release;
- cursorPhysics/cursorWorld pull geometry;
- original selectedBird logic;
- rubberBandPos/rubberBandLength;
- defaultForce/shootRange physics;
- setPosition/setVelocity/applyImpulse;
- Box2D stepping;
- Stage 17 PASS criteria.

Camera reconstruction remains a separate later milestone.
