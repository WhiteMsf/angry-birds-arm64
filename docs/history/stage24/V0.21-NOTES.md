Stage 20 tests whether the recovered platform-input boundary is actually
reusable rather than a one-shot harness.

## What Stage 20 does

The harness now has a reusable two-shot input state machine:

```text
WAIT_READY
  -> PRESS
  -> DRAG
  -> RELEASE
  -> FLYING
  -> original Lua produces next birdReady/currentBirdName
  -> WAIT_READY
  -> PRESS
  -> DRAG
  -> RELEASE
  -> FLYING
```

The harness never writes `currentBirdName`, never sets `birdReady`, never
chooses the second bird, and never directly launches either body.

It only publishes the same screen/LBUTTON input boundary already proven in
Stage 17.

## Important experiment

Stage 19 showed that `RedBird_2` becomes ready while the old
`flyingBird='RedBird_4'` is still present.

Stage 20 intentionally does **not** invent a rule that waits for
`flyingBird=nil`. On the render frame after original Lua reports
`birdReady=true` and a new `currentBirdName`, the input state machine presses
that new bird.

If original updateGame interprets that state differently, Stage 20 will fail
at the exact original Lua boundary and the next patch will follow runtime
evidence.

## Collision damage

The old laboratory name gate `birdName == "RedBird_4"` has been removed from
the recovered exactly-one-controllable collision branch. The ARMv7 branch is
classified by controllable-vs-normal object status and uses each bird's own
`damageFactors`; it is not intrinsically tied to one Level1 object name.

Therefore the naturally selected second Red Bird can use the same recovered
damage path.

Ordinary block/block damage and destructive deadBlocks/removeBlocks handling
remain enabled.

## PASS criteria

Two `ShotTrace` records must prove:

- original `birdReady/currentBirdName` selected each bird;
- PRESS, DRAG and RELEASE occur on consecutive render frames;
- original selection succeeds;
- original rubber-band math produces a valid pull;
- exactly one captured `applyImpulse` occurs per shot;
- `birdsShot` increments once per shot;
- original post-release Lua state is correct;
- each shot runs through real 30 Hz physics and reaches a natural bird
  collision before its lifecycle terminal;
- shot #1's original `nextBird` must exactly equal shot #2's bird;
- after shot #2, original Lua must either prepare another bird or complete
  the level.

No third bird is pressed in Stage 20.
