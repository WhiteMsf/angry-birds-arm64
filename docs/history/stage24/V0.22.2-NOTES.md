# v0.22.2 — correct terminal classification for original same-frame ordering

v0.22.1 successfully:

- waited until RedBird_2 released LBUTTON routing;
- selected/dragged/released RedBird_3 through original `updateGame()`;
- launched all three Level1 birds;
- naturally destroyed the final pig;
- reached `levelCompleted=true`.

The harness nevertheless reported FAIL because it also interpreted a
one-frame `levelFailedTimer` increment as a simultaneous failed terminal.

## Why both appeared in the same frame

Static reconstruction of original `updateGame()` proves this exact order:

```text
if checkLevelComplete():
    initLevelComplete()       # levelCompleted=true, levelCompleteTimer=1

if checkLevelFailed():
    initLevelFailed(dt)       # levelFailedTimer += dt
```

These are two independent checks in the same update, not `if/else`.

After the last pig is gone and all birds are exhausted, both predicates can
be true on that transition frame. `initLevelComplete()` runs first, then
`initLevelFailed(dt)` contributes a single timer tick.

That does NOT make the game enter the failed ending. On the next update,
`levelCompleteTimer > 0`, so original `updateGame()` takes the
`updateLevelEnding()` path instead of evaluating completion/failure again.

## v0.22.2 change

Terminal failure is now classified as:

```text
levelFailedTimer advanced
AND
levelCompleted == false
```

The same-frame timer pulse is still logged explicitly as an original-ordering
quirk.

No gameplay state, physics, damage, input timing, bird state, score, level
goal, or original Lua function was changed.
