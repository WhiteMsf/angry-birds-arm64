# v0.23.7 — Stage 22.7: recovered physics promoted to normal gameplay

## Closed by Stage 22.6

The A/B idle audit demonstrated that changing only the box/polygon shape radius
from upstream Box2D's default (~0.01) to the ARMv7-recovered Rovio value `0.1f`
removes the Level1 SmallPiglette's zero-input landing damage.

## What changes in 22.7

`PhysicsBridge::createBox()` now always applies:

```cpp
shape.m_radius = 0.1f;
```

This is no longer selected by an audit mode. It is part of the reconstructed
normal gameplay path. Circle radii are unchanged.

The complete Stage 22/21 gameplay path is rerun, with an added regression gate
that sums all `DamageTrace` mutations whose object name contains `Pig` before the
first original input press. The harness intentionally defers the first press until
frame 120, safely beyond the old frame-83 idle-damage event. The required result
is exactly zero mutations / zero damage throughout that soak.

## What this does NOT claim

This does not prove that every parameter of the Rovio Box2D fork is recovered.
In particular, gravity `(0,10)` and any other fork-specific solver/shape behavior
should remain on the fidelity-audit list until independently tied back to ARMv7
static/dynamic evidence.

## Next major milestone

Stage 23 starts renderer reconstruction: retain the now-working gameplay core,
recover sprite-sheet texture mapping from the original `.dat` metadata, decode or
upload the original PVR/PVRTC texture assets, reproduce pivots/UVs/transforms and
then move from offline replay toward a real GLES framebuffer on Android.
