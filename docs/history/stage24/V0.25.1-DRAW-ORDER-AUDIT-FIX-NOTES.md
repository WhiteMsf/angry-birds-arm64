# v0.25.1 — Stage 23.6C draw-order audit fix

This release changes only the ARMv7 provenance gate in the Stage 23.6C PowerShell harness. Gameplay, Lua, Box2D, GLES1 rendering, camera, interpolation, Hashtable ordering, and draw-pass implementation are unchanged from v0.25.0.

## Why v0.25.0 stopped early

The original ARMv7 binary calls `Particles::draw(gr::Context*)`, whose mangled symbol is `_ZN9Particles4drawEPN2gr7ContextE`. On the user's NDK/LLVM build, `llvm-objdump --disassemble-symbols=GameLua::drawGame` emitted the branch target without the external callee's symbol text, so the old substring gate `Particles4draw` produced a false negative before the ARM64 build started.

## Fix

The auditor now:

- writes the `drawGame` disassembly before validation, so failures remain inspectable;
- keeps the structural markers (`#0x87`, `#0x89`, `#128`, `Hashtable`) strict;
- resolves `MaskedImage::render()` and `Particles::draw(gr::Context*)` from the same ARMv7 ELF;
- parses each callee's address dynamically;
- requires `GameLua::drawGame()` to branch to the resolved address, independent of whether LLVM prints the callee name beside the branch.

No fidelity gate was removed or weakened: the direct call relationship is now checked more robustly.
