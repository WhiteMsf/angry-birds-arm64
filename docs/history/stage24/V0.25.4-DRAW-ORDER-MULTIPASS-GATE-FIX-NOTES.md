# v0.25.4 — Stage 23.6C multipass evidence-gate fix

The v0.25.3 runtime reached the full Level1 terminal state, but the Stage 23.6C evidence gate rejected `draws > kaEntries`. That assumption was wrong.

ARMv7 `GameLua::drawGame()` pass0 checks the body inverse-mass field and layer. The later flag87/flag89 pass checks those presentation flags and layer but does **not** exclude inverse-mass-zero objects. Therefore a RenderObjectData can legally be emitted in more than one pass.

v0.25.4:
- preserves the recovered four-pass renderer unchanged;
- replaces `draws <= Hashtable entries` with `uniqueDraws <= Hashtable entries`;
- requires `uniqueDraws + multiPassRedraws == draws`;
- requires Level1 to actually exercise at least one multi-pass redraw;
- reports `uniqueDraws` and `multiPassRedraws` per snapshot;
- counts changed sprites per unique object instead of per draw call;
- clarifies pass0/pass1 as `b2Body.m_invMass ==/!= 0` in the audit report.

No physics, Lua, camera, texture-state, input, or Box2D behavior is changed by this fix.
