# v0.26.10 — Stage 24.7 recovered missing-sprite semantics

## Why v0.26.9 stopped before build

The v0.26.9 PowerShell preflight assumed `SETTINGS_BG` had to occur in exactly
one original menu `.dat`. A recursive user-side probe over the complete
`assets/data` tree found no SETTINGS-named asset and found the literal
`SETTINGS_BG` only inside `scripts/gamelogic.lua`.

That initially looked like an asset omission, but the ARMv7 binary resolves the
ambiguity directly.

## ARMv7 behavior recovered

`game::LuaResources::getSpriteBounds(lua::LuaState*)` reads two strings and
calls `game::Resources::getSpriteWidth(bundle, sprite)` and
`game::Resources::getSpriteHeight(bundle, sprite)`. It always pushes two Lua
numbers. Both Resources functions return integer 0 if the requested sheet or
sprite is absent. They do not throw. Likewise, `getSpritePivotX/Y` return 0 on
a missing lookup.

Therefore `res.getSpriteBounds("", "SETTINGS_BG")` returning `(0,0)` is a valid
original-engine outcome. The reconstructed binding was wrong to raise a Lua
error merely because `SpriteDB::find` returned null.

## Changes

- remove the `SETTINGS_BG` unique-owner preflight;
- missing `res.getSpriteBounds` -> `0,0` with one-time telemetry;
- missing `res.getSpritePivot` -> `0,0` with one-time telemetry;
- absent `SETTINGS_BG` no longer aborts Stage24 startup;
- retain menu SPRT metadata loading and the v0.26.9 Stage23 audit-scope fix;
- APK versionCode 2610 / versionName 0.26.10.

No original runtime assets are included in this bootstrap ZIP. The user's own
extracted 1.4.2 assets are staged locally by the build script.
