# v0.26.101 — Stage 24.31.4a Original EGL_Image / RenderBatcher Contract Audit

## Why this stage exists

Stage 24.31.4 experimentally moved target-sized UI atlas UVs from sprite edges
toward texel centers. User screenshots showed that some long seams disappeared
while corner/cap seams remained. That is useful A/B evidence, but it does **not**
prove the original ARMv7 engine implemented the same rule.

The recovered ARMv7 `game::SpriteSheet::drawSprite(...)` delegates integer
source rectangle coordinates and floating destination dimensions to the image
backend through a virtual draw call. Therefore source-rectangle -> UV/pixel
center semantics belong below SpriteSheet unless the original backend proves
otherwise.

## This audit

`tools/stage24314a_egl_image_draw_contract.py` reads the untouched ARMv7 shared
library locally and captures:

- every `gr::EGL_Image::draw(...)` symbol and full function body;
- `gr::EGL_RenderBatcher::*` candidates, especially add/flush/draw paths;
- the original `game::SpriteSheet::drawSprite(...)` body as provenance;
- direct branch/call targets mapped back to symbols;
- indirect/virtual call sites;
- floating-point arithmetic and final GL submission signals where visible.

The audit intentionally does not decide that `+0.5/-0.5`, pixel snapping,
inclusive rectangles, or projection offsets are original until raw ARMv7 code
supports that conclusion.

## Runtime behavior

No new renderer behavior is introduced in this stage. The Stage 24.31.4
center-sampling experiment remains active so the already-observed screenshots
stay reproducible, but it is explicitly classified as non-canonical A/B
reference behavior.

The next implementation stage (24.31.4b) should replace that conditional path
with one centralized image-subrect backend matching the recovered ARMv7
`EGL_Image`/RenderBatcher semantics.
