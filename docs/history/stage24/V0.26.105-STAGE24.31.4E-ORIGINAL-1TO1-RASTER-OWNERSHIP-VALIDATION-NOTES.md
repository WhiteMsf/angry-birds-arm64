# v0.26.105 — Stage 24.31.4e Original 1:1 Raster Ownership Validation

## Purpose
Diagnostic A/B only. This revision does **not** claim a final modern presentation solution.

The Stage 24.31.4d atlas audit proved that the original UI atlases use directional extrusion:
- 1-pixel horizontal stretch strips duplicate their edge texels left/right;
- 1-pixel vertical stretch strips duplicate their edge texels top/bottom;
- 1x1 center texels are surrounded by matching texels;
- natural-size corner sprites are not necessarily extruded on their joining edges.

That layout is safe under the recovered ARMv7 `edge-to-edge UV + GL_LINEAR` contract when natural-size pieces are rasterized 1:1.

The Stage 24.20.1 WVGA debug harness currently maps logical 854x480 directly into a ~1922x1080 physical viewport on the user's modern device (~2.25x magnification before sampling). That changes the sampling semantics of every natural-size UI piece.

## Runtime change
Only when the existing WVGA debug display mode is active:
- logical Context remains 854x480;
- physical Surface remains untouched;
- viewport becomes exactly 854x480, centered;
- therefore one logical unit equals one framebuffer pixel;
- large black mattes are expected and intentional.

No changes to:
- sprite UV math (edge-to-edge remains canonical);
- original POT texture backing reconstruction;
- GL_LINEAR sampling;
- atlas pixels;
- Lua menu layout;
- blend state;
- tutorial logic;
- gear / Golden Egg behavior.

## Validation
Run `test-stage24-ui-raster-ownership.ps1` and inspect the Poached Eggs episode card and first-run tutorial popup. If seams disappear only under the 1:1 viewport, Stage 24.20.1 pre-raster scaling is proven to violate the original atlas/raster contract.

The eventual modern presentation solution should then preserve a 1:1 legacy render target and scale the **already-composited frame** as a presentation step, rather than magnifying each legacy sprite before rasterization.
