# v0.26.107 — Stage 24.31.5 Menu RenderState2D Contract + Passive Score Audit

## Scope

Stage 24.31.4 is closed and unchanged. The legacy renderer still rasterizes the
complete game at literal 854x480 / 1:1 and only the completed frame is scaled by
the outer modern presentation layer.

This revision returns to the two deferred menu micro-fidelity issues:

- Main Menu settings gear disappears/moves incorrectly while its rotation is active;
- About/Credits Golden Egg star/aura effect rotates but drifts away from the egg.

The revision is **audit-first**. It does not special-case either sprite and does
not yet change the ARM64 transform model. The next implementation must come from
the recovered original `RenderState2D` producer/consumer contract.

## Original RenderState2D frontier

Previous runtime evidence already proved that untouched Lua drives nonzero
rotation for both targets. ARMv7 `GameLua::setRenderState` also proved the
progressive 2/4/5/7 argument forms and writes translation, scale, sine/cosine
rotation fields, and pivot into `RenderState2D`.

`tools/stage24315_renderstate2d_contract.py` now follows the original backend
further through:

- `GameLua::setRenderState(lua::LuaState*)`;
- `EGL_Context` RenderState2D get/set boundaries;
- `EGL_RenderBatcher::isBatchable/add/render/flush`;
- `EGL_Shader_Default::begin()`.

The purpose is to recover how the copied 92-byte state is actually consumed by
the ARMv7 renderer before replacing the current ARM64 composed OpenGL matrix.

Anti-fix rule: do not add sprite-name branches for `MAIN_SETTINGS` or
`GOLDEN_EGG_STAR_EFFECT`. One recovered global transform semantic must explain
both.

## Passive score-fidelity audit

The user also reported that earning three stars in 1-1 may feel harder than
expected. This revision intentionally does **not** change scoring. It adds a
read-only observer around the already-restored score ledger.

For a normal completed run it records:

- untouched Lua `Max score for X-Y` output;
- silver/gold/eagle thresholds from the loaded `starTable`;
- score constants already owned by Lua;
- every change in global `score` together with per-`scoreTable` bucket deltas;
- whether a delta occurs during gameplay or after the completion gate;
- bird-shot/bird-counter state around those changes;
- score at the first `levelCompleted` transition;
- final level-complete `RESULT_STARS_*` sprite and high-score presentation.

All new runtime records use `action=OBSERVE_ONLY`. The observer never calls
`updateScore`, never writes `score`, never changes `scoreTable`, and never edits
star thresholds or remaining-bird bonus values.

A final-score mismatch alone is not evidence of a regression. Interpretation
must compare threshold/max-score provenance, bucket deltas, completion timing,
remaining-bird bonus timing, and result-star presentation together.
