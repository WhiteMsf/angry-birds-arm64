## Architectural bug

The previous ARM64 bridge interpreted `setRenderState` as a global OpenGL model matrix:

1. `drawSprite` first built vertices in screen/world coordinates.
2. `setRenderState` then loaded a model matrix that rotated/scaled those already-positioned coordinates.
3. A local pivot such as `(27,26)` therefore acted near the global origin and made the gear/aura travel across or off the screen.

The original ARMv7 `gr::EGL_Image::draw` does not consume `RenderState2D` that way. It preserves each image draw destination and transforms each image-local corner around the render-state pivot:

```
world = drawOrigin + translation + pivot
      + M * (localCorner - pivot)

M = R(angle) * S(scaleX, scaleY)
```

Relevant recovered state fields in the original `EGL_Image::draw` body are the affine components at `+0x10..+0x1c`, translation at `+0x20/+0x24`, and pivot at `+0x30/+0x34`.

## Implementation

- `stage24132SetRenderState` stores the recovered state and leaves `GL_MODELVIEW` identity.
- New `stage24315bTransformQuad` applies the recovered affine rule per draw.
- Normal sprites, bitmap-font glyphs and Lua `drawRect` use the same per-draw consumer.
- Original atlas behavior remains unchanged: edge-to-edge UV, recovered POT backing, and Stage 24.31.4f 854x480 1:1 internal raster + outer modern presentation.
