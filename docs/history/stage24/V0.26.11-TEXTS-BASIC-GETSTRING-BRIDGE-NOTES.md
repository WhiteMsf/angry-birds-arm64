# v0.26.11 — Stage 24.8 TEXTS_BASIC / res.getString bridge

The v0.26.10 device trace advanced the untouched `createMenuPages()` closure
from PC 2497 to PC 2635. Bytecode recovery identifies PC 2635 exactly as:

    res.getString("TEXTS_BASIC", "TEXT_SCORE_SPRITE")

A second call later in the same original closure requests
`TEXT_PLAY_SPRITE`.

Static ARMv7 recovery shows that the original `Resources::getString` resolves
a `TextGroupSet` / `TextGroup`, and that `createTextGroupSet()` calls
`TextGroupSet::loadLocaleCodes()`. The 1.4.2 localization container is parsed
as the original big-endian KA3D/TEXT v1 chunk layout:

- `LDAT`: locale codes (readUTF)
- `LIDS`: localization IDs (readUTF)
- `TXGP`: one value table per locale (readUTF)

This stage packages the user's own untouched
`assets/data/localization/TEXTS_BASIC.dat` at build time, parses it natively
on ARM64, chooses the Android configuration language when present (with
English fallback), and exposes `res.getString`.

The missing-key fallback returns the requested ID, matching the recovered
`TextGroup::get` behavior.

Menu-bootstrap failures remain non-fatal so the live Level1 Surface remains
usable while the next original UI dependency is identified.

This is still a diagnostic reconstruction stage. It does not yet render the
result/menu page and does not claim complete locale/platform-shell fidelity.
