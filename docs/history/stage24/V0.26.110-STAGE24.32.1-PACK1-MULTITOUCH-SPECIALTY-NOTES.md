restores a two-pointer Android input surface for the already-existing original
camera zoom consumer, and makes 1-10 a live audit of the untouched Blue-bird
`CLUSTER_BOMB` specialty branch.

## Multitouch boundary

The former Stage24 bridge deliberately exposed only one pointer. This version
tracks Android pointer count and a second coordinate pair. Lua `touchcount` now
receives the actual active pointer count.

For gameplay pinch, the Android compatibility producer measures the logical
span between pointers and applies its delta to `zoomLevel`. It does **not** call
`setWorldScale`, alter camera top-left, or synthesize a second LBUTTON action.
Untouched `doItAllCamera()` remains the scale/clamp/camera owner.

The `0.00124999997` sensitivity is evidence-derived from the original
`updateGame` bytecode path (`dy * scalar -> zoomLevel`). This does **not** claim
that the exact historical Android Java/NDK pinch producer has been recovered.

## Blue / 1-10 boundary

Prior untouched `updateGame` bytecode recovery proves a `CLUSTER_BOMB` branch
that creates two additional circles (`name.."a"` and `name.."b"`), copies bird
properties, records `parentName`, applies rotation/velocity, and inserts the new
objects into `birds`.

This build does not implement a Blue-specific native split. It transports the
original 1-10 (`Level8`) and observes `birdSpecialtyAvailable`, `birdSpecialty`,
`flyingBird`, `birds`, and native `createCircle` events. If Blue splits, that is
the original Lua branch successfully consuming existing ARM64 bindings. If it
fails, the diagnostic frontier identifies the missing compatibility surface.
