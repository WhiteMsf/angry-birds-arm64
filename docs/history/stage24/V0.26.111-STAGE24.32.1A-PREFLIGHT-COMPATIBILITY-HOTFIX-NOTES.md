# v0.26.111 — Stage 24.32.1a — Progression Preflight Compatibility Hotfix

## Symptom

`test-stage24-pack1-multitouch-specialty.ps1` stopped before compilation with:

`Stage 24.32.0 progression expansion preflight failed exit=2`

## Root cause

The inherited Stage 24.32.0 contract encoded two implementation-shape assumptions from v0.26.109:

1. it required the literal required-input prefix `@($scripts,$level1,$level57,$level53,$blocksDat...)`;
2. it required the old three-level progression verifier and one isolated `getNextLevel(Level57)` probe.

Stage 24.32.1 legitimately expanded those structures to require Level3/6/2/4/5/7/8, verify ten mapping entries, and probe the progression chain in a loop. The runtime intent was still valid, but the old static gate rejected the new source shape.

## Fix

`tools/stage24320_progression_expansion_contract.py` now validates semantics rather than the frozen v0.26.109 text shape:

- Level53 must still be a required build input alongside scripts/Level1/Level57/core assets;
- the map verifier may be the original three direct comparisons or an expanded expected-table comparison whose prefix is Level1, Level57, Level53;
- the stock next-level probe may be the original direct Level57 probe or the expanded progression-chain loop containing Level57.

All anti-hack checks remain active: no forced `levelName=Level53`, no `if Level57 -> Level53`, and no Level57-as-Level53 alias copy.

## Runtime delta

None. Stage24 gameplay/input/camera/physics/score/save/specialty code is byte-for-source unchanged from v0.26.110 except for this build-time Python contract and documentation.

## Validation

Run the same command:

`powershell -ExecutionPolicy Bypass -File .\test-stage24-pack1-multitouch-specialty.ps1`

The Stage 24.32.0 preflight should now pass, followed by the Stage 24.32.1 preflight and normal Android build/install.
