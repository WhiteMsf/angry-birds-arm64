# v0.26.12 — Stage 24.9 original font bootstrap / `res.useFont`

## Evidence that triggered this stage

The v0.26.11 device run reached `levelCompleted=true`, created the original
`levelComplete`/`levelFailed` pages, updated `highscores`, and then failed at
post-level result processing with:

```
attempt to call field 'useFont' (a nil value)
stack: useFont -> setFont -> updateLevelEnding -> currentGameMode
```

The original stripped Lua `updateLevelEnding()` calls `setFont(fontBasic)` at
this boundary. The original `setFont()` is only a thin Lua wrapper around
`res.useFont(name)`.

## Static ARMv7 recovery

`LuaResources::useFont(lang::String)` is a thin bridge to
`Resources::useFont(const lang::String&)`.

`Resources::useFont()`:

1. looks up the requested font name in the font hashtable;
2. if present and non-null, selects that font and stores the requested name;
3. if absent, tries the font hashtable's default `Ptr<IFont>` slot;
4. that slot is initialized null by the hashtable constructor, so on the clean
   startup path an unknown font returns without throwing or changing selection.

The real startup splash path calls `createAssets()` before `initialize()`.
The untouched Lua `createAssets()` calls `loadFonts()`. Stage24 bypasses the
splash path, so `loadFonts()` had never executed and `fontBasic`/`fontMenu`
were never initialized.

The untouched `loadFonts()`:

- calls `selectFontProfile()`;
- resolves `FONT_BASIC` and `FONT_MENU` through
  `res.getString("TEXTS_BASIC", ...)`;
- calls `res.createBitmapFont()` for basic/menu/score/big-numbers/LS-small
  fonts;
- uses `fontPath` to construct the logical paths.

For `deviceModel="android"` with logical 480x320 Stage24 dimensions,
`selectFontProfile()` resolves the original `480x320` font profile.

## What v0.26.12 changes

- exposes the layout-derived logical root `fontPath = "data/fonts"`;
- stages the user's untouched 480x320 font DATs into the APK at build time, including the conditional Game Center pair;
- materializes those DATs into app-private runtime storage;
- restores `res.createBitmapFont` as a diagnostic registration bridge that
  verifies each requested original font file exists and records its font key;
- restores `res.useFont` with the recovered non-throwing select/fallback
  semantics;
- explicitly replays the untouched original `loadFonts()` Lua closure before
  `initialize()`, matching the ordering of the original splash asset path
  without re-enabling the entire splash/createAssets resource factory;
- logs `fontBasic`, `fontMenu`, created-font count, and each later `useFont`;
- preserves the post-completion Lua fault quarantine and all existing Level1
  gameplay behavior.

## Deliberate non-claim

This stage does **not** yet implement glyph rasterization or the final bitmap
font renderer. `drawString` remains a headless/no-op presentation boundary.
The goal of Stage24.9 is to restore the original font bootstrap and font
selection semantics so the untouched post-level state machine can advance to
its next real boundary.
