# v0.26.124 — Stage 24.38.2 — levelFailed Menu / Boot Handoff Regression

## Runtime trigger

The long v0.26.123 Pack3 closure run completed all remaining Poached Eggs
levels, but the retained Android logcat captured one real Lua fault during a
3-19 (`Level22`) terminal-failure attempt:

`attempt to index global 'levelFailed' (a boolean value)`

The fault occurred after all three birds had been spent, two goals remained,
and untouched `initLevelFailed(dt)` had advanced `levelFailedTimer` past the
1.5 second failure gate. The old post-complete diagnostic quarantine kept the
surface alive; the user later restarted the app and finished the level.

## Root cause

Stage24.29.0's synthetic handoff from the reconstructed splash presenter back
to untouched `updateMenu` contained:

`if levelFailed ~= nil then levelFailed = false end`

That line confused two different original concepts:

- `levelFailed` is the menu-page **table** created by untouched
  `initializeMenu()` (`levelFailed.items` has 24 items in the recovered menu
  bootstrap);
- `levelFailedTimer` is the gameplay failure-state timer consumed by untouched
  `initLevelFailed(dt)` / `updateLevelEnding()`.

Most QA runs restarted a failed attempt before the 1.5 s automatic failure menu
was reached, so the corruption remained latent from v0.26.89 through v0.26.123.
The long Pack3 stress run finally exercised the exact path.

## Fix

Remove only the Stage24.29.0 assignment to `levelFailed`.

The boot handoff still resets `levelCompleted=false`, selects `mainMenu`, marks
it for preparation, and enters untouched `updateMenu`. It does **not** create,
replace, select, or modify the failure page/timer.

A read-only boot observer records the post-handoff type/item count and
`levelFailedTimer`. New static contract rejects any boot-time boolean/nil
assignment to `levelFailed`, any Level22 special case, forced failure page, or
failure-timer override.

## Poached Eggs closure evidence from v0.26.123

All 3-6..3-21 levels reached completed highscores. The final `Level81` result
used score 81,370 / 1 star. Pressing the original final Next did **not** route to
an invented 3-22: untouched Lua transitioned through `gameFinished` into the
original `gameComplete` page and persisted `settings.gameCompleted=true`.

The diagnostic's oldest Pack3 gameplay had already fallen out of the Android
log buffer, so load counts are only lower bounds for the retained tail. The
retained log still shows especially heavy retry stress including Level30 >=10,
Level40 >=8, Level22 >=19, Level89 >=4 and Level81 >=6 loads.
