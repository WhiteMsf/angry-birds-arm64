# v0.26.126 — Stage 24.40.0 — Mighty Hoax polygon native reconstruction

## Runtime failure that triggered this stage

v0.26.125 entered stock Mighty Hoax 4-1 (`data/levels/pack4/LevelP2_103`).
Theme4 transport was already alive: the level loaded, boxes/circles materialized,
and `StaticBlockTheme01_03_1` received `INGAME_THEME_GROUND_4`. The first new
contract occurred immediately afterwards:

```text
clearVertices
addVertex
addVertex
addVertex
createPolygon argc=12
LUA ERROR: attempt to index field ? (a nil value)
```

The stack is `createObject -> loadLevelInternal -> update`. `createPolygon` was
still the inherited Stage8 zero-return generic stub, so untouched Lua could not
find the object it had just asked native GameLua to create. The user-visible
symptom was ground only, then exit.

## Original ARMv7 authority

The already-retained Stage24.22.5 disassembly proves:

- `GameLua::clearVertices()` and `GameLua::addVertex(float,float)` exist;
- `GameLua::createPolygonLua(String,String,float,float,float,float,float,float,float,bool,bool,float)` is the public 12-argument wrapper;
- `GameLua::createPolygon(RenderObjectData*,String,float,float,float,float,float,float,float)` copies the accumulated GameLua vertex array;
- it calls `b2PolygonShape::Set(b2Vec2 const*, int)`;
- it creates a normal Box2D body and fixture;
- polygon skin is the recovered Rovio `0.1f`;
- density/friction/restitution remain direct fixture inputs.

## ARM64 reconstruction

Stage24.40.0 replaces only three old stubs: `clearVertices`, `addVertex`, and
`createPolygon`. The untouched Lua producer still decides when vertices are
cleared/appended and which objects are polygons. The bridge uses the exact same
body/fixture defaults already validated for createBox/createCircle, registers
the generic render metadata, and materializes `objects.world[name]` so original
`createObject()` can continue filling strength/material/damage state.

There is no LevelP2_103 or Mighty Hoax-specific geometry/physics branch.
