## Ovi banner diagnosis

The Mighty Hoax card is clickable and functional, but its stock card still
renders `AVAILABLE_ON_APP_STORE`. The original Lua explains why:

1. `createMenuPages()` always creates the episode-card `appStore` child.
2. `prepareMenuPage()` calls untouched `hasLevelPack2()`.
3. `hasLevelPack2()` forms the first Pack4 path from
   `levelSelectionPagesExtra.items[firstLevelIndex].folder + filename + ".lua"`
   and calls native `checkForLuaFile()`.
4. On true it shows normal score/stars, sets the stock level-selection callback
   and hides `appStore`; on false it follows the unavailable-pack visual path.
5. The ARM64 binding was still the Stage24.31.0 audit nil-stub.

This is therefore not a device-model/SKU fix and not an Ovi-specific override.

## Reconstructed native boundary

`l_stage24310_checkForLuaFile()` now:

- accepts the untouched logical Lua path;
- resolves it with the generic `stage24128_resolve_lua_resource_path()` already
  used by the level loader;
- tests the resolved path read-only;
- returns exactly one Lua boolean;
- logs logical/resolved/existence/caller context.

The original ARMv7 `GameLua::checkForLuaFile(lang::String)` body resolves through
the app path, opens a FileInputStream, returns true on success and false on its
caught missing-file path. No file is created or mutated.
