# v0.26.14 / Stage 24.11 — original level-selection context bridge

Runtime v0.26.13 proved `starTable` itself is correct (`Level1` -> 30000/32000/17000), but `updateLevelEnding()` still failed immediately after `setFont(fontBasic)` with `attempt to index field ? (a nil value)`.

Static bytecode audit identifies the skipped state: `initialize()` sets `levelName = ""`, while the normal `handleGameModeChange()` level-selection branch sets `levelName = item.filename`, `levelFolder = item.folder`, current level/theme/world numbers, attempt count, and then loads the level. `gotoLevelSelection()` also sets `levelSelectionPages = levelSelectionPagesBasic`. Stage24 bypassed both functions and called `loadLevelInternal()` directly.

Stage 24.11 now derives the target filename from the physical Level*.lua path, locates that exact item in the original `levelSelectionPagesBasic.items` table built by `initializeMenu()`, and restores the selection-derived globals before `loadLevelInternal()`. No star thresholds or menu-item fields are hardcoded.

It also logs the real runtime `levelName` in result dispatch. Visual result/menu rendering remains intentionally unimplemented.
