# v0.26.140 — Stage 24.44.2a — Clean-build preflight fix

## Failure in v0.26.139

The Stage24.44.2 implementation itself had already been inserted into
`stage24_live_surface.cpp`, but its build-time contract script unconditionally
opened `stage24-output/stage24.22.0-level-failed-contract.txt`.

That report is not a build artifact. It is created by `pull-stage24-live-log.ps1`
*after* a live device capture. Therefore a fresh extracted v0.26.139 tree had an
impossible dependency cycle: build 44.2 required evidence that could only exist
after building, installing, running, and pulling logs.

## Fix

- `stage24442_level_limit_frozen_contract.py` now treats the Stage24.22.0 runtime
  report as optional historical evidence.
- If an old Stage24.22.0 report exists, the strong `frozen` / `removeObject`
  constant check is still performed.
- On a clean tree, the preflight instead verifies that the untouched-Lua evidence
  dumper and relevant owners remain wired, reports the historical check as
  `SKIP_CLEAN_BUILD`, and continues.
- The actual Stage24.44.2 gameplay implementation is unchanged: positive-mass
  dynamic objects crossing minX/maxX or synchronized y>20 receive
  `object.frozen=true`; untouched Lua owns removal.
- The build script now snapshots `$LASTEXITCODE` immediately after the Python
  preflight pipeline, before writing the report to disk.

This is a tooling/preflight repair only; no physics, lifecycle, bounds, score,
rendering, or Lua gameplay semantics were changed.
