# v0.26.141 — Stage 24.44.3 — Original Android `setGameOn` closure

## Runtime baseline carried forward

The v0.26.140 / Stage24.44.2a live capture closes the original level-limit
consumer reconstruction. Poached Eggs 1-1 produced three independent right
limit crossings. `RedBird_4`, `RedBird_2`, and `RedBird_3` each received the
reconstructed native `frozen=true` write immediately after crossing `maxX=104`.
Untouched Lua then removed them after 1, 1, and 2 observed outside frames
respectively, replacing the old ~19.4 second off-map linger. After the third
shot the ordinary failure timer advanced and the stock `levelFailed` page was
entered. No Lua, native, Java, or GPU fatal failure was captured.

## `setGameOn` ownership

`GameLua::setGameOn(bool)` was the final Stage24.43/44 lifecycle stub still
marked observe-only. The original ARMv7 body is tiny but indirect:

1. load the constructor-supplied `framework::App*` from `GameLua+0x20`;
2. load `App+0x4`, the framework `OSInterface*`;
3. negate the Lua boolean;
4. invoke virtual slot `+0x18` on the OSInterface.

Stage24.44.3 resolves the original AndroidOSInterface vtable from the shipping
ARMv7 ELF. Because the constructor stores `vtable+8` as the object vptr, the
called entry is `vtable+8+0x18`; it must resolve exactly to
`framework::AndroidOSInterface::allowSleep(bool)`.

The shipping Android `allowSleep(bool)` symbol is exactly four bytes and
contains only `bx lr`. Therefore the platform-specific effect in Angry Birds
1.4.2 Android is **no effect**. `setGameOn(true)` still semantically requests
`allowSleep(false)` and `setGameOn(false)` requests `allowSleep(true)`, but the
Android implementation discards that request.

The ARM64 reconstruction now records this as `ORIGINAL_ANDROID_NOOP`. It does
not synthesize `FLAG_KEEP_SCREEN_ON`, lifecycle pausing, body activity changes,
or any other modern behavior absent from the original Android binary.
