# v0.26.145 / Stage 24.46.1

## Why this stage exists

Stage24.46.0 successfully entered The Big Setup and loaded `LevelP4_421` / Theme9, but the live renderer stopped fail-closed on frame 2065 because Theme9 is the first recovered theme to set `bgLayers[i][5] = false`. The exact live table proved four such layers:

- `PARALLAX_CRANE_1`: parallax 0.8, scale 1.0, offset 565
- `PARALLAX_CRANE_2`: parallax 0.85, scale 1.3, offset 645
- `PARALLAX_CRANE_3`: parallax 0.9, scale 1.6, offset 755
- `PARALLAX_CRANE_4`: parallax 0.95, scale 2.0, offset 822

The failure was therefore not a missing asset, Lua error, Box2D error, or driver issue. It was an intentional reconstruction boundary.

## Original ARMv7 contract

The already-captured `GameLua::drawBackground()` disassembly at `0x4fc58..0x4ffbc` contains both branches. `0x4fe38..0x4fe40` selects repeat vs non-repeat. The non-repeat path at `0x4fce0..0x4fd5c` performs:

```text
transformX = offset - trunc(offset)
drawX      = offset - (topLeftX * parallax) / layerScale
drawY      = -topLeftY / layerScale
drawSprite exactly once
```

No tiling loop is entered for this branch.

## Reconstruction

Stage24.46.1 implements that exact geometry in both:

- gameplay scene background rendering;
- menu-owned theme background rendering.

The repeating path used by Themes1-8 remains unchanged. Theme9 scene data still comes entirely from untouched `blockTable.themes["theme9"]`; there is no Theme9-specific branch in the renderer.

On 9-1 the runtime should emit four `NONREPEAT_DRAW` witnesses and no `LIVE GPU frame FAIL`. If that closes, continue 9-1..9-15 with stock Next to audit the rest of The Big Setup page 1.
