# v0.26.15.10 / Stage 24.12.9 — LevelComplete invisible-menu action audit

Diagnostic-only stage. No gameplay/menu/progression semantics are changed.

Live v0.26.15.9 proved the Stage24.12.8 resource-path resolver works, but a random
post-completion touch at logical (412.06,271.25) changed `levelName` from Level1
to Level57 and entered `updateLoading`. Because `drawMenu` is intentionally still
headless/no-op, the user cannot see which menu action/hitbox was activated.

This stage adds read-only telemetry:

- calls original `getNextLevel("Level1")` after the recovered Level1 selection context;
- repeats the progression probe when LevelComplete enters `updateMenu`;
- dumps all `levelComplete.items` selected fields (position, dimensions, sprite,
  action/returnValue, filename/folder, level indices, visibility/enabled state);
- logs PRE/POST state for every real touch while `currentGameMode == updateMenu`,
  including logical coordinates, `levelName`, `currentMenu`, game-mode function,
  and whether level/mode changed.

The expected result distinguishes:

1. progression-data divergence (`getNextLevel("Level1")` itself returns Level57), or
2. a different invisible menu item/hitbox being activated (probe returns Level2 or
   another expected value, but the touch changes levelName differently).

No fallback, level alias, Level57 stub, or forced Level2 behavior is introduced.
