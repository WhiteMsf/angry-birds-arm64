# v0.26.15.13 / Stage 24.13.2 — visible Level Complete sprite/box renderer

## Evidence closed by v0.26.15.12

Stage 24.13.1 ran the untouched original `drawMenu` closure in isolation after
`currentMenuPage.name == "levelComplete"` and it returned normally. The exact
observed Level Complete draw contract was 37 calls consisting only of:

- `setRenderState` (5- and 7-argument forms)
- `drawRect(r,g,b,a,x0,y0,x1,y1,filled)`
- `res.drawSprite` (4-, 6-, and 8-argument forms)
- `res.drawString` (6-argument form)

No later native/resource function was missing in that menu path.

## Stage 24.13.2 scope

This revision turns only the already-proven non-text primitives into real GLES1
output:

- `setRenderState`
- `drawRect`
- `res.drawSprite`

The original `drawMenu` closure remains preserved under
`__stage24_original_drawMenu`; the public global remains the historical headless
boundary so the original update loop is not allowed to enter a partially
reconstructed renderer. The native live renderer invokes the untouched alias
itself after the gameplay scene on every `updateMenu` frame whose
`currentMenuPage.name` is `levelComplete`.

`res.drawString` intentionally remains headless/audit-only. Bitmap-font glyph
pixel rendering is the next separate boundary; this revision does not fake text.

## `res.drawSprite` contract implemented

The three argument shapes observed directly in Stage 24.13.1 are implemented:

```text
res.drawSprite(sheet, sprite, x, y)
res.drawSprite(sheet, sprite, x, y, vAnchor, hAnchor)
res.drawSprite(sheet, sprite, x, y, vAnchor, hAnchor, width, height)
```

For the anchored forms the original Lua `drawBox` evidence establishes the
ordering as vertical anchor first, horizontal anchor second. Supported values in
the observed path are `TOP`/`VCENTER`/`BOTTOM` and
`LEFT`/`HCENTER`/`RIGHT`. The 8-argument form stretches the full source sprite
to the requested target rectangle. The 4-argument form uses the sprite pivot
from the original SPRT metadata.

Empty sprite names and zero-sized target rectangles remain no-ops. Missing
sprite metadata remains non-fatal, matching the already-recovered ARMv7 resource
lookup behavior. If an existing sprite needs an atlas whose pixel format is not
yet recovered, the renderer fails at that exact concrete `res.drawSprite` call
instead of guessing.

## Original menu texture transport

The build script discovers texture filenames from the untouched menu SPRT DAT
files themselves; no atlas filename is guessed.

- PVR assets are staged byte-for-byte and use the already-proven strict
  one-level RGBA4444 PVR-v2 path when compatible.
- PNG assets are losslessly decoded at build time to a tiny `ABR8` transport
  (`magic + width + height + exact RGBA8 pixels`) by
  `tools/png_to_rgba8.py`, which uses only Python's standard library.

The PNG conversion is only a pixel transport into the native ARM64 APK. It does
not alter the original source tree and is not ARMv7 execution, translation or
emulation.

Menu atlases referenced by the wider staged DAT set but not parseable by this
first renderer are skipped during startup. They become an error only if the live
original draw path actually requests a sprite that needs one, preserving the
project's first-concrete-divergence rule.
