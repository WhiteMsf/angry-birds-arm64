# v0.26.15.13.1 — Stage 24.13.2a

Packaging-only fix for the first visible Level Complete renderer build.

Live v0.26.15.13 evidence showed that the app never reached Lua/GLES rendering: runtime asset preparation failed opening `stage24/menu-textures/BACKGROUNDS_GE_1.pvr`, even though the DAT-derived manifest and source staging reported all ten menu transports.

This revision does not change Lua, physics, resource semantics, or drawing code. After `aapt` and native-library insertion, `tools/apk_ensure_asset_dir.py` opens the actual APK, verifies every file under `assets/stage24/menu-textures`, injects only entries silently omitted by `aapt`, and re-verifies the resulting ZIP before zipalign/signing.

Expected build line:

```
[stage24.13.2a-apk] menu asset verification PASS files=11 already=... injected=...
```

(11 = manifest.tsv + 10 DAT-derived texture transports.)
