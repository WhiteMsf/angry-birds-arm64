# v0.26.15.13.3 — Stage 24.13.2c — menu texture manifest CRLF normalization

Live v0.26.15.13.2 proved that `AAssetManager_openDir("stage24/menu-textures")` sees all 11 entries, including `BACKGROUNDS_GE_1.pvr.bin`, while the subsequent `AAssetManager_open()` call still returned null.

Root cause: the build writes `manifest.tsv` on Windows. `std::getline()` removes LF but retains CR, so the parsed transport name was actually `BACKGROUNDS_GE_1.pvr.bin\r`. `%s` logging made the carriage return visually disappear, making the failing name appear identical to the directory listing.

Changes are transport-only:
- build writes `manifest.tsv` with explicit LF-only line endings;
- native parser defensively strips one trailing `\r` before TSV parsing;
- no Lua, Box2D, sprite semantics, GLES renderer, menu logic, fonts, or input changes.
