# v0.26.15.14 — Stage 24.13.3 legacy Android responsive menu scaling

## Trigger

Stage 24.13.2c rendered the untouched Level Complete menu successfully on a
Samsung S24 FE, but it was globally oversized. The live Surface is 2248x1080
while the historical Stage8 presentation path fits the whole 480x320 harness
to height, producing a 1620x1080 viewport and a 3.375x UI magnification.

## Evidence used

- The untouched runtime image family used by this Android build is `864x480`.
- Public Rovio-era `select_profiles.lua` code retained by AngrySDK selects the
  `864x480` Android asset/font family once `screenHeight >= 480` for the normal
  non-HD Android path.
- The later Rovio-era Level End implementation lays out/shades against the
  actual `screenWidth`/`screenHeight`, rather than treating the 480x320 box as
  a permanently full-screen canvas.
- A contemporaneous December 2010 GameDev StackExchange answer reports that
  Angry Birds avoids arbitrarily magnifying its raster assets. This is
  corroborative community evidence, not an exact ARMv7 implementation proof.

## Reconstruction in this stage

Gameplay/camera/physics remain on the already-closed 480x320 Stage24 contract.
Only menu/result presentation changes:

1. Before untouched `initializeMenu()`, derive a legacy Android menu canvas
   with logical height 480 and width preserving the real `ANativeWindow`
   aspect ratio.
2. On the S24 FE 2248x1080 this resolves to 999x480.
3. Build original menu tables with those globals, then restore 480x320 before
   Level1 loads.
4. Once `levelCompleted`/`updateMenu` is active, publish the menu dimensions
   again so untouched result preparation/update/draw code uses the same canvas.
5. Render menu primitives with a matching GLES1 projection/viewport.
6. Map menu touches through that same presentation transform.

No sprite coordinates, anchors, UVs, result values, physics, camera state or
font metrics are manually changed. `res.drawString` stays headless.

## Why this is still a reconstruction boundary

The exact native 1.4.2 policy for displays far beyond 2010 Android resolutions
has not yet been recovered. The 480-high aspect-preserving canvas is an
evidence-backed compatibility reconstruction, chosen to restore the legacy
Android asset/profile relationship without perturbing gameplay. The next live
run should validate both visual scale and the untouched Lua item coordinates.
