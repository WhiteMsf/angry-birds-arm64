# v0.26.15.15 / Stage 24.13.4 — original bitmap-font LevelComplete + animation trace

## Closed input from Stage 24.13.3

The S24 FE 2248x1080 run validated the legacy-Android 480-high responsive menu
presentation. `initializeMenu()` is prepared with a 999x480 logical canvas and
the GPU menu projection uses the same 999x480 presentation at 2.25x. The
result box/buttons/stars visually match the period reference closely.

## First concrete missing visual boundary

The original `drawMenu()` trace contains six `res.drawString()` calls for the
LevelComplete result (`1-1`, level-complete text, score label/value and highscore
label/value). In Stage 24.13.3 those calls were intentionally headless while the
box/sprite renderer was proven.

Stage 24.13.4:

- retains the Stage 24.13.3 480-high responsive menu canvas;
- extends the already-parsed KA3D/FONTv1 records to retain each glyph's exact
  `(x,y,width,height,pivotY)` rectangle;
- discovers the font bitmap image name directly from untouched FONT DAT headers
  at build time (no guessed filename);
- stages only the two textures proven by the LevelComplete trace:
  `FONT_BASIC` and `FONT_BIG_NUMBERS`;
- preserves PVR bytes or losslessly transports PNG as ABR8, exactly like the
  already-proven menu atlas transport;
- uploads those font atlases to GLES1;
- replaces the headless `res.drawString` boundary with bitmap glyph quads using
  the current original `res.useFont()` selection, recovered tracking/string
  width, glyph rectangles and vertical pivots;
- supports the exact LevelComplete 6-argument drawString shape and
  LEFT/HCENTER/RIGHT + TOP/VCENTER/BOTTOM anchors.

Missing glyphs retain the already-recovered width semantics: zero glyph width,
but requested characters still participate in inter-character tracking.

## Animation telemetry

The original drawMenu is already invoked on every updateMenu frame. Stage
24.13.4 records the first 150 LevelComplete frames at a sparse cadence:

- full-screen shade alpha;
- `STARS_BIG_*` sprite selected;
- `RESULT_STARS_*` sprite selected;
- whether `NEW_HIGHSCORE_BG` is drawn;
- number of bitmap-font glyph GPU draws;
- total menu GPU draws.

This distinguishes an actually static update path from animation that was
already running but visually obscured by the missing text layer.

- menu layout math / item positions;
- menu sprite UVs / stretch semantics;
- audio;
- missing theme/background/foreground/slingshot presentation layers.
