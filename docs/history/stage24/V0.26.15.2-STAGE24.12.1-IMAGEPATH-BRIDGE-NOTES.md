# v0.26.15.2 — Stage 24.12.1 imagePath bridge

## Evidence from the first v0.26.15.1 live run

The compile-only fix succeeded and the AArch64 APK installed, but the game
thread exited before Level1 rendered.  The first original-Lua divergence was:

```
ORIGINAL initializeMenu bootstrap FAIL lastProto=releaseImages pc=28:
?:0: attempt to concatenate global 'imagePath' (a nil value)
```

The traced Lua stack was:

```
releaseImages -> prepareMenuPage -> createMenuPages -> initializeMenu
```

This dependency is newly visible because Stage 24.12 intentionally stopped
replacing `prepareMenuPage` with a noop.

## Minimal reconstruction

The untouched 1.4.2 extraction used by the Stage24 build stores image resources
under:

```
data/images/864x480/...
```

The same bootstrap already restores the layout-derived logical roots
`levelPath = "data/levels"` and `fontPath = "data/fonts"`.  This substage adds
only:

```
imagePath = "data/images"
```

before the original menu bootstrap runs.

This value is deliberately labeled as derived from the original asset layout
plus the observed `releaseImages` CONCAT boundary.  It is not yet claimed as an
independently recovered native ARMv7 literal.

## What is intentionally NOT changed

- no fallback/default current font is invented;
- no `clipText` behavior is changed;
- no prepareMenuPage logic is modified;
- no drawMenu implementation is added;
- no menu image payloads are added merely to silence errors;
- no physics, input, camera, renderer or lifecycle behavior changes.

The v0.26.15.1 run also later showed `clipText: current bitmap font metrics
unavailable for '<none>'`, but that occurred only after the earlier partial
`initializeMenu` failure.  Stage 24.12.1 therefore does not patch it yet.  The
next live trace decides whether it disappears once the original menu bootstrap
gets past `releaseImages`, or becomes the next genuine boundary.
