# v0.26.15.3 — Stage 24.12.2 — `res.releaseSpriteSheet` bridge

The v0.26.15.2 live run proved that the `imagePath = "data/images"` bridge is
accepted by the untouched Lua: `releaseImages` advanced from PC 28 (CONCAT on
`imagePath`) to PC 29, where it attempted to call the missing native field
`res.releaseSpriteSheet`.

Observed stack:

```
releaseSpriteSheet [C field]
releaseImages
prepareMenuPage
createMenuPages
initializeMenu
```

This substage registers only `res.releaseSpriteSheet`.

Stage24 currently has no emulated native `Resources` SpriteSheet cache. The
SPRT DAT metadata database used for bounds/render reconstruction is a separate
bootstrap structure, and GLES1 textures are separately owned by the renderer.
Therefore the minimal state-correct behavior for a release call against this
empty resource cache is a non-fatal void operation. The binding records the
exact path/argc and intentionally does not erase the independent SpriteDB.

No `loadSpriteSheet`, menu renderer, font-current workaround, physics, Lua
script, or `prepareMenuPage` behavior is added or changed. If the original Lua
reaches another missing resource method, that becomes the next differential
boundary.
