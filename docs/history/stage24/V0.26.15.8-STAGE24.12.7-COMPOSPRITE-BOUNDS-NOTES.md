# v0.26.15.8 — Stage 24.12.7 — original tutorial composprite bounds

First live divergence after Stage 24.12 font/menu bootstrap completed:

- `loadLevelInternal()` enters original `prepareMenuPage()` for the tutorial page.
- exact traced failure: `prepareMenuPage pc=9178`.
- bytecode PCs 9172..9178 resolve and call `res.getCompoSpriteBounds("", tutorials.items[i].sprite)`.
- Lua expects four results (`CALL C=5`) and immediately subtracts min/max pairs.

This revision restores only that resource boundary.

## Original data used

The untouched 1.4.2 Android tree contains:

- `data/images/864x480/TUTORIALS_SHEET_1.dat`
- `data/images/864x480/TUTORIALS_composprites.dat`

The latter is staged into the APK and parsed as legacy KA3D `COMP` metadata.

## Semantics

Each legacy COMP entry names a composite and lists child sprite names with signed x/y offsets. Child dimensions and pivots come from the already-loaded normal `SPRT` metadata. Bounds are the union:

- `x0 = childX - childPivotX`
- `y0 = childY - childPivotY`
- `x1 = childX + childWidth - childPivotX`
- `y1 = childY + childHeight - childPivotY`

`res.getCompoSpriteBounds(bundle, name)` returns `(minX, minY, maxX, maxY)`.
A missing composite returns `(0,0,0,0)`, matching the recovered resource-style missing lookup behavior and independent Ghidra-derived implementation.

No renderer, physics, input, camera, font, clipText, drawMenu, or audio behavior is changed.
