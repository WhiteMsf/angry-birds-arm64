# v0.26.151 / Stage24.47.2 — distance-joint spring solver audit

## Why this stage exists

The Stage24.47.1 rubber-contact audit did **not** justify an ad-hoc restitution fix. The latest Golden Eggs run exercised `ExtraTrampoline_* / BLOCK_SUPER_BALL / material='rubber'` with restitution `5.5`, but those objects are also tied together by a large network of the exact type=1 distance joints reconstructed in Stage24.43.1.

The user's persistent visual description is that the reconstructed rubber structure feels **softer / more "molenga"** than the original. That symptom is better matched by a spring-constraint difference than by blindly changing contact restitution.

The original createJoint contract is already closed:

- native Box2D joint type: `e_distanceJoint` / type 3;
- `frequencyHz = 4.0f`;
- `dampingRatio = 0.5f`;
- `collideConnected = false`;
- original coordType branches and rest-length construction are retained.

Therefore Stage24.47.2 does not tune any of those values. It audits the solver itself.

## New ARMv7 native acquisition

During build, `tools/stage24472_distance_joint_solver_native_audit.py` uses the untouched ARMv7 `libangrybirds.so` plus LLVM nm/objdump to acquire:

- `b2DistanceJoint::b2DistanceJoint(...)`;
- `b2DistanceJoint::InitVelocityConstraints(...)`;
- `b2DistanceJoint::SolveVelocityConstraints(...)`;
- `b2DistanceJoint::SolvePositionConstraints(...)`.

The same report prints the pinned Box2D 2.1.2 `b2DistanceJoint.cpp` source used by the port so the next analysis can compare the original Rovio instruction/dataflow against the public candidate without guessing.

Output:

- `stage24.47.2-distance-joint-solver-native-audit.txt`

This acquisition is diagnostic only. A PASS means the relevant original bodies/source were captured, **not** that equivalence has already been declared.

## New runtime spring witness

Immediately before each untouched `world.Step(dt, 10, 10)`, the bridge snapshots every reconstructed distance joint whose Lua-owned endpoint material is `rubber`.

After the same Step, it ranks the most strained joints and emits:

- `[stage24.47.2-spring] FRAME` — network-level maxima/counts;
- `[stage24.47.2-spring] BEFORE`;
- `[stage24.47.2-spring] AFTER`.

Fields include:

- joint name and endpoint object names;
- rest length;
- current length;
- absolute length error;
- normalized strain `(currentLength-restLength)/restLength`;
- frequency and damping ratio reported by the actual `b2DistanceJoint`;
- world anchors;
- endpoint linear velocities;
- relative anchor velocity along the joint axis;
- post-Step reaction-force vector and magnitude;
- delta strain across the Step.

Any rubber BeginContact opens a short high-detail window so the frames around an actual impact are sampled densely. Outside that window, only sparse periodic top-strain samples are emitted. Total output is capped.

The observer never calls Box2D or Lua mutators.
