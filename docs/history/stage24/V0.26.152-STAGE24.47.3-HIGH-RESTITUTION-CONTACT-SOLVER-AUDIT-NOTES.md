# v0.26.152 — Stage 24.47.3 — High-Restitution Contact Solver Cross-Proof

## Why this stage exists

Stage24.47.2 quantified the visible "molenga" rubber behavior: the GE3 trampoline network reached very large normalized distance-joint strain, and 8-3 reproduced the same family. However, the untouched ARMv7 `b2DistanceJoint` constructor and all three solver methods structurally match the pinned Box2D 2.1.2 implementation, including the already-restored Rovio `b2_linearSlop=0.05`. The apparent alternative hypothesis, a wrong physics cadence, also closes: original `GameLua::update(float)` calls `b2World::Step(0.033333335, 10, 10)` exactly as the ARM64 reconstruction does.

That leaves the high-restitution contact path as the next shared boundary. `ExtraTrampoline` contacts live-prove fixture/Lua `restitution=5.5`. This stage does **not** assume 5.5 is wrong.

## Native acquisition

`tools/stage24473_high_restitution_contact_solver_native_audit.py` dumps from the untouched ARMv7 library:

- `b2ContactSolver::b2ContactSolver(...)`
- `b2ContactSolver::InitVelocityConstraints(...)`
- `b2ContactSolver::SolveVelocityConstraints()`

beside the pinned Box2D 2.1.2 `b2ContactSolver.cpp` and the stock `b2_velocityThreshold=1.0f` setting.

The purpose is to resolve the original restitution `velocityBias` and one-/two-point normal-impulse dataflow before changing any coefficient.

## Runtime isolation witness

The retained Stage24.47.1 observer now additionally emits Stage24.47.3 lines with:

- joint-edge count on each body;
- currently touching contact count on each body;
- `isolatedCandidate=true` when neither body has joints and each has at most the sampled touching contact;
- BeginContact relative normal velocity;
- mixed restitution;
- the stock 2.1.2 bias implied from that BeginContact sample;
- post-Step relative normal velocity;
- diagnostic bounce ratio.

The report explicitly labels those ratios as coarse diagnostics because BeginContact occurs before island gravity/constraint solving; they are not claimed to expose Box2D's internal `velocityBias`.

## Reproduction strategy

Primary: **Golden Egg 2 / `LevelGE_2`**, using free `ExtraRubberBall` / `BLOCK_BEACHBALL` bodies. This removes the 4 Hz distance-joint network from the contact response.

Cross-check: **Danger Above 8-3 / `LevelP3_306`**, using `ExtraTrampoline` bodies in the spring network.

No level-specific behavior is added. The observer is material/contact-owned only.

## No mutation

This stage does not call `SetRestitution`, `SetFriction`, `SetLinearVelocity`, `SetAngularVelocity`, `ApplyImpulse`, `ApplyForce`, `CreateJoint`, `DestroyJoint` or any gameplay/Lua state mutation.
