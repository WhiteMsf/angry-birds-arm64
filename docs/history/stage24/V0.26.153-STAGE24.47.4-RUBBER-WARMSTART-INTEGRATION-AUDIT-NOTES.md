# v0.26.153 — Stage24.47.4 rubber warm-start / island integration audit

## Why this stage exists

Stage24.47.2 and Stage24.47.3 eliminated the easy fixes for the long-standing
rubber/trampoline fidelity mismatch:

- the original ARMv7 `b2DistanceJoint` soft-spring solver is structurally the
  pinned Box2D 2.1.2 implementation;
- `frequencyHz=4.0`, `dampingRatio=0.5` and rest-length construction remain the
  recovered original contract;
- the original fixed step is exactly `1/30` with `10,10` iterations;
- the original high-restitution contact constructor uses
  `velocityBias = -restitution * vRel` below the 1.0 threshold, with no clamp on
  the observed rubber restitution `5.5`;
- the one-point normal impulse accumulation path matches pinned 2.1.2.

The latest 47.3 runtime did not hit `LevelGE_2`; it exercised 8-3 and GE3, both
spring networks. It also showed many rubber bodies ending a step at exactly
`|v| * dt = 2`, so the integration clamp is active in the visible response.

## Important telemetry correction

Stage24.47.1 labeled its PostSolve velocity as `postSolver`. In Box2D 2.1.2 the
listener's `PostSolve` is emitted from `b2Island::Report`, after velocity
constraint finalization, linear/angular clamp + position integration and the
position-constraint loop. The old values remain useful, but they are
**post-island/clamped**, not the raw output of `SolveVelocityConstraints()`.
Stage24.47.4 makes this timing explicit.

## Native acquisition

The build now dumps untouched ARMv7 bodies and pinned source for:

- `b2Contact::Update` (manifold-ID matching / warm-start impulse carryover),
- `b2ContactSolver::FinalizeVelocityConstraints`,
- `b2Island::Solve`,
- `b2Island::Report`,
- `b2World::Step`,
- `b2CircleContact::Evaluate` when present.

This is diagnostic only. No solver constant is inferred or changed.

## Runtime witness

For touching rubber contacts:

- `CONTACT_PRE` records the previous-step manifold history visible immediately
  before `World::Step`,
- `PRESOLVE` runs from the no-op listener hook after `b2Contact::Update` has
  matched old/new contact IDs and therefore captures the **actual warm-start
  impulses presented to the island solver**,
- `CONTACT_POST` records the finalized manifold impulses after the completed
  step and whether the pair is an isolated-contact candidate.

For rubber bodies:

- pre/post position, velocity, angle and angular velocity,
- actual position delta,
- `|v| * dt` versus mutable Rovio `b2_maxTranslation`,
- `|w| * dt` versus Box2D `b2_maxRotation = pi/2`,
- explicit `linearCap` / `angularCap` flags,
- joint/contact counts.

All runtime code is observe-only.

## Focused repro

1. `LevelGE_2`: free `ExtraRubberBall` / beachballs, 2–3 impacts; no completion.
2. `LevelP3_306` / 8-3: one clear `ExtraTrampoline` impact and a few seconds of
   network motion.

If GE2 is missed again, GE3 remains useful for the network side, but the free
ball sample is still the cleanest way to separate contact response from spring
network behavior.
