# v0.26.154 — Stage24.47.5 FP contraction / rubber order audit

## Why this stage exists

Stage24.47.4 closed the remaining obvious warm-start and integration-clamp
branches for the long-standing rubber/trampoline fidelity mismatch. The ARMv7
oracle and pinned Box2D 2.1.2 now agree on the recovered constants, fixed 30 Hz
step, distance-joint soft spring, contact restitution path, warm-start matching,
solver ordering at the island phase level, and linear/angular integration caps.

The next architecture-level difference is floating-point contraction. The
original ARMv7 physics paths visibly use scalar soft-float helper calls such as
`__mulsf3`, `__aeabi_fadd` and `__subsf3`, which impose separate float32
rounding boundaries. A modern AArch64 Clang build may otherwise contract an
`a*b+c` expression into FMADD/FMSUB and round only once.

## Change

`box2d212` and `stage24_live_surface` now compile with:

```
-ffp-contract=off
```

This is a generic numerical-fidelity compiler policy. It does not special-case
Golden Eggs, 8-3, rubber, restitution or any recovered object type.

The post-build Stage24.47.5 binary audit disassembles both the untouched ARMv7
oracle and the generated AArch64 library. It requires an ARMv7 separate-float
helper witness and fails closed if FMADD/FMSUB/FNMADD/FNMSUB appears inside the
relevant AArch64 Box2D/live-physics functions.

## Runtime order witness

The live bridge also logs the exact Box2D world joint linked-list order once per
rubber level. This is observe-only and explicitly does **not** assume that the
world linked-list order is identical to the per-island DFS constraint ordering.
It is retained as evidence if disabling FP contraction does not explain the
visual stiffness mismatch.

Stage24.47.5 additionally resets only diagnostic line budgets when the active
level changes. Stage24.47.4 previously allowed GE3 to consume the BODY_POST
budget before the later 8-3 control case. No gameplay/physics state is reset.
