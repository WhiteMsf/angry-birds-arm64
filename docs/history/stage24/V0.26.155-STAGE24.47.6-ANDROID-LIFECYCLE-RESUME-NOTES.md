# v0.26.155 — Stage24.47.6 — Android lifecycle / Recents resume

## Symptom
Opening Android Recents/multitasking and immediately returning to the app replayed the startup splash and returned to the main menu.

## Root cause
The NativeActivity wrapper incorrectly treated `APP_CMD_TERM_WINDOW` as complete engine destruction by calling `stage24_stop_engine()`. Android can emit `TERM_WINDOW` for a temporary Surface loss while the process/activity remains alive, so the next `APP_CMD_INIT_WINDOW` started a new game thread, Lua state, Box2D world and renderer.

## Reconstruction
- `APP_CMD_TERM_WINDOW` now pauses the existing engine, resets touch, gates audio, waits for the engine thread to become quiescent, and releases only the wrapper's `ANativeWindow` reference.
- Lua state, Box2D world, engine thread, EGLDisplay, EGLContext and uploaded textures remain alive.
- `APP_CMD_INIT_WINDOW` publishes the new `ANativeWindow`; when the engine is already running it requests an EGL window-surface rebind instead of starting a new engine.
- The engine thread destroys only the old `EGLSurface`, creates a new window `EGLSurface`, and makes the existing context current on it before advancing another game frame.
- `APP_CMD_DESTROY` remains the only normal NativeActivity command that calls `stage24_stop_engine()`.
- Audio lifecycle gating restores the pre-background game-owned output state instead of blindly forcing sound on.

## Expected live witness
A Recents round-trip should contain:

`TERM_WINDOW action=PRESERVE_ENGINE`

then:

`INIT_WINDOW action=REBIND_EXISTING_ENGINE coldBoot=no`

then:

`SURFACE_REBOUND ... contextPreserved=yes ... luaPreserved=yes box2dPreserved=yes splashReplay=no`

There must not be a second `Stage24 native ARM64 game thread starting` or a second startup splash caused solely by the Recents round-trip.

## Scope
No Lua menu/page, level, score, save, Box2D body or gameplay state is synthetically changed by Stage24.47.6.
