# v0.26.158 — Stage24.48.0 Release Candidate Audit

## Purpose

Begin 1.0 homologation from the proven v0.26.157 / Stage24.47.6B runtime without changing gameplay, physics, renderer, Lua ownership, audio or Android lifecycle code.

## Runtime freeze

The stage ships a SHA-256 baseline manifest for:

- `stage24_live_surface.cpp`
- `CMakeLists.txt`
- `stage24-android/AndroidManifest.xml`

The RC preflight fails if any of those drift from the v0.26.157 baseline.

## New audits

- `stage24480_release_candidate_contract.py`: verifies Release build, arm64 ABI, single arm64 runtime injection, FP contraction policy, lifecycle preservation markers, external original-asset ownership, and inventories release-envelope debt.
- `stage24480_apk_payload_audit.py`: post-signing ZIP audit; requires exactly `lib/arm64-v8a/libangryarm64.so` and rejects any ARMv7 native payload.
- `stage24480_runtime_smoke_audit.py`: scans pulled stdout/stderr/logcat for Lua/GPU/native/lifecycle failures and validates the expected Recents preserve/rebind sequence when exercised.
- `test-stage24-release-candidate.ps1`: real-profile integrated regression sweep. It never clears the user's save.

## Known release-envelope debt

48.0 deliberately leaves the development envelope untouched while the engine is homologated:

1. `android:debuggable=true`
2. stale manifest `versionName`
3. Stage24 application label
4. Stage24 package identity decision
5. Android debug-key signing
6. `stage24-debug.apk` output naming

These are packaging/release tasks, not gameplay fidelity defects.

## Acceptance

48.0 passes when static/runtime safety gates are clean and the human oracle reports no material visual/gameplay/audio/UI divergence during the integrated sweep. Clean-profile testing and final release-envelope cleanup follow as separate stages so they cannot destroy or contaminate the long-running real save.
