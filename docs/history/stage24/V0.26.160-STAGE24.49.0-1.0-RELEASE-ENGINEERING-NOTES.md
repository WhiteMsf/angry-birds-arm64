# v0.26.160 — Stage24.49.0 — 1.0 Release Engineering

## Goal

Turn the already-homologated Stage24 runtime into a real 1.0 release envelope without changing the reconstructed engine.

## Frozen engine

The two files that define the native runtime build remain byte-for-byte on the v0.26.157 baseline:

- `stage24_live_surface.cpp` SHA-256 `3313964f7a57a7329a4c74ea0ce63351120080093a197e6c787546a1d4fb84e0`
- `CMakeLists.txt` SHA-256 `8d172b4246090d5320de68cedfed91d88ede7a7fab3ffc68c2a22910a755c6c6`

No gameplay, Box2D, Lua, renderer, audio, save, Golden Egg or Android lifecycle behavior is intentionally changed by Stage24.49.0.

## Two envelopes, one engine

`build-stage24-live-surface-touch-arm64.ps1` now has explicit `Audit` and `Release` flavors.

### Audit

- package `dev.angryarm64.stage24`
- debuggable, for `run-as`, full diagnostics and historical-profile regression
- local audit/debug signing identity
- output `angry-arm64-stage24-audited.apk`

### Release

- package `dev.angryarm64.angrybirds`
- `versionName=1.0.0`
- `versionCode=1000000`
- `android:debuggable=false`
- label `Angry Birds`
- original launcher icon sourced locally from the user's original extraction/APK
- output `Angry-Birds-1.0.0-arm64-v8a.apk`
- permanent external PKCS12 release key
- explicit APK signature schemes v1 + v2 + v3

The release pipeline fails closed unless the `lib/arm64-v8a/libangryarm64.so` payload in the Audit APK and Release APK has the exact same SHA-256 and byte length.

## Signing model

The permanent release key lives outside the project under:

`%USERPROFILE%\.angry-arm64\signing\angry-birds-release.p12`

The password is prompted interactively and exists only in the current PowerShell process environment while signing. The source/release folders never receive the private key or password. Only the public PEM certificate and certificate fingerprints are copied to the release folder.

Losing the private release key means losing the ability to ship signature-compatible updates outside a store-managed app-signing system. Back it up offline.

## 16 KB page-size gate

The final native ELF is audited with `llvm-readelf -lW`. Every PT_LOAD segment must report alignment of at least `0x4000` (16 KB). This is build-time future-proofing for modern 64-bit Android page-size compatibility.

## Distribution tree

`build-angry-birds-1.0.0-release.ps1` creates:

- `dist/1.0.0/release/`
  - signed final APK
  - clean source archive (no proprietary assets, saves or signing secrets)
  - release notes
  - build provenance
  - public signing certificate/fingerprints
  - SHA256SUMS
- `dist/1.0.0/audit/`
  - audited Stage24 APK
  - release-engineering contract report
  - exact native-payload equivalence proof
  - 16 KB ELF report
  - package/certificate reports
  - best-effort backup of the historical Stage24 `settings.lua` / `highscores.lua`
  - final diagnostics after acceptance

## Final acceptance

Run:

```powershell
powershell -ExecutionPolicy Bypass -File .\test-angry-birds-1.0.0-final.ps1
```

This builds both envelopes, creates/reuses the permanent key, runs the packaging gates, asks for a short broad regression on the historical audited profile, then installs the final package side-by-side as a naturally clean profile for first-run/tutorial/save/restart/lifecycle acceptance.

The release package deliberately differs from the Stage24 development package so the old audited install and its historical save remain intact while the final package receives a clean 1.0 identity and release signature.
