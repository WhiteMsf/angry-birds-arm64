# v0.26.162 / Stage24.49.0B — release manifest staging hotfix

Release-engineering-only hotfix. The reconstructed runtime remains frozen.

## Live failure proven by 0.26.161

The fully audited envelope built and packaged successfully. The final Release flavor then compiled and linked `libangryarm64.so`, but legacy `aapt` rejected the flavor source file `AndroidManifest.release.xml` with `ERROR: No AndroidManifest.xml file found.`

## Fix

- The selected flavor manifest is copied byte-for-byte to `stage24-apk-work/package-manifest/AndroidManifest.xml` before invoking legacy `aapt`.
- SHA-256 equality between source flavor manifest and staged canonical manifest is fail-closed.
- The true `aapt` exit code is captured before removing the SUBST bridge, so cleanup can no longer turn an actual packaging error into `aapt package failed: 0`.
- ADB presence probing is non-fatal when no device is attached; device absence is handled by the later interactive acceptance phase instead of killing pure release packaging.
- Audit envelope metadata advances to 0.26.162 / versionCode 26162.

No changes to `stage24_live_surface.cpp` or `CMakeLists.txt`.
