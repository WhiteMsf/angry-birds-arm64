# v0.26.18 — Stage 24.14.1 MaskedImage contract audit

## First concrete divergence

Stage 24.14.0 proved that the original visible **Next Level** transition is correct:
`Level1` -> `Level57`, where this data set uses `Level57.lua` for visual level 1-2.
The loader resolves and executes the file, reconstructs 33 physics/render objects, and
reinstalls the particle runtime surface.  The first failure is not Lua or loading; it is
the strict Stage 23.6C renderer gate:

```
[stage23.6C-order] unsupported Level1 MaskedImage objects=15
[angry-stage24] LIVE GPU frame FAIL
```

The old Stage 23.6C implementation intentionally rejected any `setTexture()` object
because Level1 contained none and MaskedImage rendering had not yet been reconstructed.

## This build

No visual approximation is added.  Stage 24.14.1 keeps the GPU failure strict and
surfaces the exact contract needed for the reconstruction:

- `setTexture(name, texture)` now retains the exact texture string in native metadata;
- each call logs object, texture, current sprite, mass, layer, and draw flags;
- on the first MaskedImage render boundary the runtime dumps every masked object in
  KA3D Hashtable iteration order, including position/angle and the exact SPRT mask
  sheet/rect/pivot where available;
- the Windows build searches the user's `Downloads\angry-re` tree for the original
  ARMv7 `libangrybirds.so`; when present it uses the NDK LLVM tools to dump the exact
  `MaskedImage::render(gr::Context*)` symbol into
  `stage24-output\stage24.14.1-armv7-maskedimage-render.txt`;
- `pull-stage24-live-log.ps1` prints both the live MaskedImage contract and the static
  ARMv7 disassembly report.

## Expected test

Complete 1-1 and press Next.  `Level57` should again load 33 objects and the process
should stop at the renderer boundary, but this time the pull log should contain:
