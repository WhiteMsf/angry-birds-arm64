# v0.26.21 — Stage 24.14.2 MaskedImage producer/shader contract audit

## Evidence entering this revision

Level57 (visual 1-2) loads successfully and creates 33 world objects. The first
GPU frame then reaches the intentionally strict MaskedImage boundary with 15
static terrain objects.

The original ARMv7 `MaskedImage::render()` was recovered at `0x60500`, size
`0x390`. It constructs a triangle-list vertex format containing position plus
two texture-coordinate sets, renders through a shader, and clears three
temporary float4 arrays after the flush.

The live contract also proves that the Level57 masked objects use mask sprites
`GROUND_BLOCK_03`, `GROUND_BLOCK_04`, and `GROUND_BLOCK_05` from
`INGAME_BLOCKS_1.pvr`, with `INGAME_THEME_GROUND_1` as their texture.

## Change

Static audit only; no gameplay/render semantics changed.

At build time, when the original ARMv7 `libangrybirds.so` is available:

1. Run `llvm-nm -S -C` and capture every symbol containing `MaskedImage`.
2. Disassemble every executable MaskedImage text/weak-text symbol by exact
   address + symbol size, avoiding fragile mangled-name selection.
3. Dump the evidence-derived `.rodata` window `0x145180..0x145280` referenced
   by the recovered `MaskedImage::render()` PC-relative shader parameter loads.
4. Write:
   `stage24-output\stage24.14.2-armv7-maskedimage-full.txt`.
5. Keep every llvm failure nonfatal; no audit helper may block the native build.

The existing Stage 24.14.1 live `setTexture`/15-object audit and strict
`MaskedImage` renderer gate remain unchanged.

## Purpose

Recover the producer method(s) that fill the three transient arrays and the
exact shader parameter names before implementing the first native ARM64
MaskedImage terrain renderer. No `drawSprite` approximation is introduced.
