# v0.26.34 — Stage 24.15.6

## Exact gameplay viewport / physical presentation matte separation

Observed on the 2248x1080 device surface:

- gameplay logical size: 480x320
- fitted gameplay viewport: 1620x1080 at x=314, y=0
- Stage24.15.3/15.5 correctly recovered theme1 color: RGB(148,206,222)
- the scene itself rendered correctly
- the theme color also appeared in the left/right physical pillarbox area

Root cause:

`glViewport()` does **not** constrain `glClear()`. Stage24.15.3 selected the gameplay viewport and then cleared using the theme background color. The clear therefore affected the complete physical framebuffer rather than only the logical game viewport.

Stage24.15.6 restores the pre-existing presentation ownership boundary:

1. clear the complete physical framebuffer to black (presentation matte)
2. select the exact gameplay viewport
3. enable scissor with the exact same viewport rectangle
4. clear the gameplay viewport using the original theme color
5. disable scissor before normal scene rendering

This does not introduce a game-space magic number. Black belongs to the port's out-of-game presentation matte; the game-space color remains sourced from the original 1.4.2 `blockTable.themes.theme1.color` contract.

No scene geometry, parallax, UV, pivot, camera, physics, MaskedImage, progression or UI semantics are changed.

Expected one-time diagnostic:

`Stage24.15.6 gameplay presentation matte PASS ... matte=BLACK themeClear=SCISSORED`
