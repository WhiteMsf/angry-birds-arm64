# v0.26.35 — Stage 24.16.0

## Android presentation / resolution contract audit

### Status
Diagnostic-only. No visual behavior is intentionally changed from v0.26.34.

### Question being answered
What did Angry Birds Classic 1.4.2 Android actually mean by `screenWidth`,
`screenHeight`, resource profile, camera extent and native viewport on displays
such as 800x480 / 854x480, and how should that map to a modern 2248x1080
Surface?

### Why the previous assumption is no longer accepted as proof
Stage24 historically published `screenWidth=480`, `screenHeight=320` for
playable Level1 because the early harness needed a stable logical coordinate
system. Stage24.13.3 later made menus responsive but deliberately left gameplay
at 480x320. Stage24.15.6 then correctly constrained `glClear()` to that viewport,
which exposed extremely large pillarbox bars.

The bars therefore prove what the *current harness* does; they do not prove what
the original 1.4.2 Android application did.

### Evidence guiding the audit (not implementation constants)
- The user's untouched Android asset tree currently selects/contains an
  `images/864x480` family.
- Contemporary Android beta reporting described native 800x480 rendering on
  2010 Android devices.
- Later public Rovio Lua uses screen dimensions to choose Android resource
  buckets including 320x240, 480x320 and 864x480 and keeps camera logic aware of
  `screenWidth`/`screenHeight`.

Later public code is corroboration only. This stage does not copy its values into
the 1.4.2 renderer.

### Exact audits added

`stage24.16.0-asset-profile-contract.txt`
- inventories every original image/font profile directory;
- reports exact dimensions/aspect names and file counts;
- identifies original Lua/config files owning presentation/profile keywords;
- records which profiles contain the theme1 INGAME families.

`stage24.16.0-armv7-presentation-contract.txt`
- compact presentation-related symbol table from original `libangrybirds.so`;
- disassembly of exact retained methods such as `GameLua::setRenderState`,
  `setTopLeft`, `setWorldScale`, and `gr::Context` width/height/viewport/clear
  methods when present;
- offset-preserving printable strings for screen/resolution/profile terms.

`stage24.16.0-lua-presentation-contract.txt`
- untouched loaded 1.4.2 Lua bytecode for `selectAssetProfile`,
  `selectFontProfile`, `initCameras`, `levelStartCamera`, `doItAllCamera`,
  `defaultCamera`, and `repositionScreen` when present.

`stage24.16.0-live-presentation-contract.txt`
- current `screenWidth` / `screenHeight` and original selector return values at
  pre-binding, menu bootstrap, gameplay restore, post-level-load and first
  gameplay frame;
- physical EGL Surface, GL viewport/scissor, projection matrix and camera state
  on the first gameplay frame.

### Side-effect policy
Selector probes restore `screenWidth` and `screenHeight` after every call. No
profile selector or camera closure is replaced. This revision does not widen,
stretch, crop, clamp, letterbox or otherwise reinterpret the gameplay scene.

### Next decision
Only after these reports identify the original ownership boundary do we change
presentation. No `999x480`, `864x480`, aspect clamp, camera scale or viewport
formula will be promoted into runtime merely because it looks plausible.
