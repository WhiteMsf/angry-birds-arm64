# v0.26.4 — Stage 24.1 post-completion trace + input bounds

This revision is an evidence-gathering boundary, not a fake result-screen implementation.

Changes:
- logs the active original Lua `update` closure whenever game mode changes (expected `updateGame -> updateMenu` after Level1 completion);
- logs Lua errors to Android logcat with update mode, last traced Proto name/PC and error text;
- after a Lua error **only after a proven `levelCompleted=true`**, freezes physics and quarantines the top-level update dispatch instead of terminating the NativeActivity;
- pre-completion Lua errors remain fatal (`rc=15`) so gameplay regressions cannot be hidden;
- DOWN events starting in modern-device letterbox bars are ignored; gestures started inside the 480x320 game viewport remain valid and are clamped to the game edge if the finger crosses a bar, preserving UP;
- the pull script now prints native stderr/stdout tails automatically.

No result/menu behavior is approximated in this revision. The next implementation step is driven by the exact post-completion fault captured from the original Lua path.
