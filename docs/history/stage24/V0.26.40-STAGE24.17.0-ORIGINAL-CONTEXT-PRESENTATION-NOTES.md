# v0.26.40 — Stage 24.17.0 — Original Context presentation

Stage 24.17.0 is the first implementation stage after the 24.16.x resolution audits.

## Recovered original ownership chain

The original ARMv7 binary establishes the presentation dimensions through this chain:

1. `Java_com_rovio_ka3d_MyRenderer_nativeInit` receives consecutive Java integer arguments for width and height.
2. Those values are forwarded unchanged to `gr::EGL_createContext(width, height, orientation)`.
3. `EGL_createContext` forwards them unchanged to `gr::EGL_Context`.
4. `EGL_Context::width()` and `height()` occupy the `gr::Context` vtable slots used by `GameLua::GameLua(...)`.
5. `GameLua` publishes those values as Lua globals `screenWidth` and `screenHeight`.
6. Original Lua camera code uses those globals directly when calculating visible world bounds.

`nativeResize` independently corroborates the same dimension contract by forwarding its two Java integer arguments into the context resize virtual call.

## Runtime changes

- Remove the synthetic 480x320 gameplay canvas.
- Remove the centered 1620x1080 viewport and black side matte on a 2248x1080 Surface.
- Use the complete EGL Surface/Context as the logical gameplay and menu canvas.
- Publish Context dimensions to Lua before `gamelogic.lua`/font selection, matching the original GameLua-constructor ownership boundary.
- Use Context dimensions for gameplay projection, culling, scene repetition bounds, foreground fill, readback, and Android touch mapping.
- Keep asset resolution separate from screen resolution. The untouched 1.4.2 selectors choose the `864x480` quality bucket on >=480-high Android screens.
- Stage the original `fonts/864x480` DATs required by that selector instead of the former `fonts/480x320` transport.
- Add a first-frame `Context/Lua` invariant diagnostic. `PASS` means Lua `screenWidth/screenHeight` exactly match the renderer Context dimensions.

## Deliberately not changed

- Camera formulas remain the untouched original Lua formulas; wider Context dimensions are allowed to alter framing naturally.
- No new aspect-ratio constant or compatibility crop is introduced.
- The separate possible gameplay bug reported by the user remains parked until presentation is confirmed.
