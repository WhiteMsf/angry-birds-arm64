# v0.26.42 — Stage 24.18.1 — Original slingshot Lua owner audit

Diagnostic-only. Stage 24.17.0 presentation and Stage 24.18.0 rendering remain unchanged.

Stage 24.18.0 recovered the exact original `INGAME_BIRDS_1` sprite names:

- `SLING_HOLDER`
- `SLING_SHOT_01_FRONT`
- `SLING_SHOT_01_BACK`

It also confirmed that the original Lua corpus owns `rubberBandPos`,
`rubberBandAngle`, `rubberBandLength`, and the sling sprite names, but it did
not identify the exact closure/bytecode branch that binds those resources to
runtime geometry. Implementing the sling before that point would still require
invented ordering/offsets.

Stage 24.18.1 therefore inspects the untouched 1.4.2 Lua closure tree before
native bindings replace globals. It recursively finds Protos containing the
exact sling/rubber constants and dumps only merged bytecode windows around
instructions that reference them. This avoids another whole-`updateGame` dump
while preserving enough surrounding VM instructions to reconstruct the owner.

The live runtime also reports exact original SPRT metadata for the three sling
sprites after `INGAME_BIRDS_1.dat` is parsed: sheet, texture, rect and pivot.

Output pulled into diagnostics:

`stage24.18.1-slingshot-lua-owner.txt`

No slingshot wood, holder, rubber geometry, particles, audio, score popup, HUD,
or level-failed screen is implemented in this stage.
