## Exact recovered draw order

The untouched Lua closure performs, in order:

1. transform `rubberBandPos` and `levelStartPosition` to world pixels;
2. if `currentBirdName` exists, move the rubber endpoint to the near bird edge
   using `radius` or `width*0.5`, plus the original `0.05` physics-unit margin;
3. choose `tempWorldScale` when present, otherwise `worldScale`;
4. draw `SLING_SHOT_01_BACK` at `levelStartPosition`;
5. draw rear rubber from `(baseX+20, baseY)` to the computed holder endpoint;
6. draw `SLING_HOLDER` there only when `selectedBird == nil`;
7. execute native gameplay objects (`drawGameNative`) and foreground;
8. draw front rubber from `(baseX-21, baseY-3)` to the same endpoint;
9. when `selectedBird ~= nil`, rotate `SLING_HOLDER` by `rubberBandAngle` around
   its exact sprite pivot and draw it at the endpoint;
10. reset render state and draw `SLING_SHOT_01_FRONT` at the base.

Rubber width is the recovered reciprocal expression `50/rubberBandLength`,
clamped to `[10,25]`. The bytecode passes exact RGBA `(48,23,8,255)` to
`drawLine2D`.

No coordinate was taken from a screenshot and no visual fitting constant was
added. The line primitive is emitted as a centered quad under the same recovered
world render transform; this is the GLES1 implementation of the original
`drawLine2D` surface used by the Lua contract.
