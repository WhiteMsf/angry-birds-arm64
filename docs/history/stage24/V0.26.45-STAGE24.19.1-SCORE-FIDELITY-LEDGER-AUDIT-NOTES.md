# v0.26.45 — Stage 24.19.1 — Score Fidelity Ledger Audit

Diagnostic-only scoring pass. No score constants, star thresholds, physics values, damage rules, or HUD pixels are changed.

## Why this pass exists

The untouched Angry Birds 1.4.2 Lua recovered by Stage 24.19.0 proves the original scoring contract:

- `blockDestroyedScoreIncrement = 500`
- `pigletteDestroyedScoreIncrement = 5000`
- `birdsLeftScoreIncrement = 10000`
- `birdCollision(..., actualDamageFloor)` credits `actualDamageFloor * 10` into a per-object `scoreTable[...]` bucket.
- `removeBlocks()` credits destruction bonuses into `scoreTable.blocks.score`.
- `updateScore()` recomputes global `score` as the sum of every `scoreTable[*].score` entry.

The old live telemetry incorrectly printed only `scoreTable.blocks.score` under the label `score`. This build fixes the diagnostic label/source and records the entire score table.

## New runtime ledger

`[stage24.19.1-score-ledger]` records every observed score bucket mutation, with:

- frame
- reason (`birdCollision`, `frameEnd`, baseline)
- subject/event context
- score-table key (`blocks`, `birds`, bird object name, etc.)
- before / after / delta
- global score changes as `__GLOBAL__`

The original `birdCollision` call is snapshotted immediately before and after the untouched Lua callback, so damage-score mutations can be separated from later block-removal bonuses.

## Original max-score diagnostic

Stage24 previously stubbed Lua `print()`. This hid the untouched loader's own `Max score for ...` diagnostic. The new print bridge preserves print's no-return behavior and only surfaces that exact line as:

`[stage24.19.1-score-contract] originalLua Max score for ...`

It also records the three global scoring constants after `gamelogic.lua` loads.
