# v0.26.46 — Stage 24.19.2 ordinary-contact score ownership audit

Diagnostic-only follow-up to the 24.19.1 score ledger.

## Why this stage exists

The 1-1 ledger proved that the reconstructed runtime awards:

- bird-contact damage score through original Lua `birdCollision()`;
- destruction bonuses through original Lua `removeBlocks()`;
- 10,000 points for each unused bird.

The same run ended at 28,800 points, with 8,800 earned before the two-bird
20,000 bonus. The untouched original Lua prints a theoretical maximum of
39,300 for 1-1.

Stage 10 had already recovered a remaining ARMv7 `GameLua::BeginContact`
operation on the ordinary/non-controllable collision branch:

```
floor(totalActualDamage) * 10
```

but deliberately did not reproduce it because its destination table/field had
not yet been proven. Stage 24.19.x now has enough score-table context to audit
that ownership directly.

## Runtime shadow

For every ordinary block/block BeginContact this stage records:

```
actualDamageA
actualDamageB
floor(actualDamageA + actualDamageB) * 10
cumulative shadow score
actual scoreTable.blocks.score
actual global score
```

The shadow is telemetry only. It never writes to Lua and therefore cannot
change stars, score, physics, damage, destruction, or rendering.

## Static ARMv7 audit

`tools/stage24192_block_score_ownership.py` dumps the untouched
`GameLua::BeginContact(b2Contact*)` body and score-facing native calls, plus
binary offsets for `scoreTable`, `blocks`, `score`, `blockCollision`,
`birdCollision`, `strength`, and `defence`.

The goal is to prove the exact owner of the already-recovered native score
arithmetic before implementing it.
