# v0.26.47 — Stage 24.19.3 restored ordinary-contact damage score

This stage restores a score mutation that had intentionally remained disabled since Stage 10 while ownership was unresolved.

## Untouched ARMv7 proof

`GameLua::BeginContact(b2Contact*)` resolves the score-facing literals as:

- `0x144920` -> `scoreTable`
- `0x144930` -> `blocks`
- `0x144e30` -> `score`
- `0x144938` -> `blockCollision`

The native dataflow is:

1. load `scoreTable.blocks.score` before the ordinary-contact Lua callback;
2. calculate the two recovered `actualDamage` values;
3. call original Lua `blockCollision(...)`;
4. if total actual damage is positive, execute `floorf(totalActualDamage) * 10.0f`;
5. add that delta to the score value captured in step 1;
6. write the result through `LuaTable::setNumber("score", ...)` on the `blocks` table.

This closes the ownership question from Stage 24.19.2. The scoring destination is not inferred from gameplay; it is recovered from the original ARMv7 body.

## Runtime change

The ARM64 reconstruction now reproduces that exact ordinary/non-controllable contact score update. No star thresholds, destruction bonuses, bird bonuses, damage constants, physics values, or HUD values are changed.

Runtime telemetry uses:

`[stage24.19.3-block-score-restored]`

and reports per-contact damage, delta, `blocks.score` before/after, cumulative restored score, and current global score before the next original `updateScore()` pass.
