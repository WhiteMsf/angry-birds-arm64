# v0.26.48 — Stage 24.20.0 original gameplay score HUD

This stage implements the fixed top-right score presentation recovered by the
Stage 24.19.0 untouched-Lua audit, on top of the now-validated Stage 24.19.3
score calculation.

## Recovered `drawGame()` contract

The original 1.4.2 `drawGame` bytecode at pc 0312..0550 establishes:

- current score text is `string.format("%d", score)`;
- the fixed HUD uses the already-active `fontBasic` (`FONT_BASIC` on the
  recovered Android profile);
- `oldScoreLen = max(getStringWidth(scoreText), oldScoreLen)` prevents the
  numeric column from shrinking as the score changes;
- the right edge is `screenWidth - 3`;
- localized `MI_SCORE` is drawn immediately left of the numeric column;
- when `highscores[levelName].score >= 0`, localized `MI_HIGH_SCORE` and the
  highscore occupy the first row, while current score moves down by
  `getFontLeading() + 1`;
- both rows are anchored RIGHT/TOP in screen/Context coordinates;
- optional advertising offset is
  `min(max(scoreAdOffsetY, 0), bannerHeight)` when present;
- the iPhone4 resolution branch is not selected on Android.

The same untouched closure switches to `FONT_SCORE` only at pc 0558 for the
separate `floatingScores` world-space feedback, then restores `fontBasic` at
pc 0627.  Stage 24.20.0 therefore does **not** use `FONT_SCORE` for the fixed
HUD and does not implement floating +500/+5000 text yet.

## Runtime behavior

The GLES1 renderer now draws the fixed score HUD after the foreground/front
slingshot layer, in the same Context-space presentation as the original Lua
HUD.  It is suppressed on recovered level-ending menu pages.

Telemetry:

`[stage24.20.0-score-hud]`

reports score, string width, `oldScoreLen`, optional highscore, numeric-column
width, font, leading, right-edge coordinate, ad offset and localized labels.

No score constants, star thresholds, physics, damage, camera, slingshot,
level-complete menu, or floating-score behavior changes in this stage.
