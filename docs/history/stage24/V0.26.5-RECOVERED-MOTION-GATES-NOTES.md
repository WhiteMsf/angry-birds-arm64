# v0.26.5 — Stage 24.2 recovered ARMv7 motion gates

## Why this exists

The first live builds used a provisional native shim for `hasMovingObjects`:

```cpp
speedSquared > 0.0001f || abs(angularVelocity) > 0.01f
```

With the recovered world gravity `(0,20)`, resting birds can retain solver/contact
velocities around 0.7–1.2 units/s.  The provisional threshold therefore kept the
original Lua ending logic waiting indefinitely after all birds were fired.

## ARMv7 recovery

Static reconstruction of `GameLua::update(float)` now shows the actual constants:

- linear motion gate: `vx*vx + vy*vy > 9.0f`
- angular motion gate: `angularVelocity > 0.1f`
- a separate `hasMovingObjectsZeroTolerance` branch uses `speedSquared > 0` and
  excludes RenderObjectData `flag87` objects.

The native function writes the motion booleans into Lua before the original game
update consumes them.

## v0.26.5 behavior

`sync_physics_to_lua()` now mirrors those recovered gates and exports both
`hasMovingObjects` and `hasMovingObjectsZeroTolerance`.  Stage24 logcat also emits
`LIVE motion gates` whenever the main live state telemetry changes.

This is a gameplay-fidelity correction, not a synthetic timeout.  No forced win or
forced failure is added.
