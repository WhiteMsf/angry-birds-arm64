# v0.26.51 — Stage 24.22.0 Level Failed Contract Audit

A live Level57/1-2 run exhausted all five controllable birds while a goal
remained alive.  After the last flying bird cleared, the world settled and
`hasMovingObjects=false`, but `levelFailedTimer` did not advance and
`currentGameMode` remained `updateGame`.

This proves the missing failure result is not merely an unrendered
`levelFailed` menu.  The original failure state itself is not being reached in
this runtime path.

Stage 24.22.0 is diagnostic-only:

- dumps untouched 1.4.2 Lua bytecode/constants for `checkLevelFailed`,
  `initLevelFailed`, `checkLevelComplete`, `initLevelComplete`, `updateGame`,
  `updateLevelEnding`, and `checkLevelGoalsDestroyed` before native binding
  replacement;
- logs live terminal-candidate inputs after no current/flying bird remains:
  `birdsCounter`, `birdsShot`, `birdReady`, `birdFired`,
  `hasMovingObjects`, zero-tolerance movement, `levelGoals`,
  `levelFailedTimer`, `levelCompleteTimer`, current game mode and menu pages;
- does not call `checkLevelFailed()` a second time, modify timers, synthesize a
  terminal, or render the failure menu.

The purpose is to identify the exact failed predicate before any fix is made.
