# v0.26.52 — Stage 24.22.1 Birds Controllable Lifecycle Audit

Stage 24.22.0 recovered the exact 1.4.2 failure predicate:

- if `hasMovingObjects` is true (unless `objects.doNotWaitForMovingObjects == true`), return false;
- otherwise iterate global `birds`;
- if any `birds[*].controllable` is true, return false;
- only then return true and let `initLevelFailed(dt)` advance the failure timer.

This is important because `birdsShot` and `birdsCounter` are not consulted by
`checkLevelFailed()` at all.

A previous Level57/1-2 repro reached `currentBird=nil`, `flyingBird=nil`,
`birdsShot=5`, `hasMovingObjects=false`, one or more goals alive, yet failure did
not begin.  Therefore the remaining candidate is stale controllable ownership in
the global `birds` table.

Stage 24.22.1 is diagnostic-only. It:

- logs every `birds` entry after all shots are consumed and whenever a terminal
  candidate is present;
- records key/name/definition, `controllable`, `shot`, object-world presence,
  object-world controllable/shot state, table identity, and counts;
- prints a read-only prediction of the original `checkLevelFailed()` result;
- expands the untouched `updateGame` dump through its full bytecode and adds
  `getNextBird` / `fillInNextBird` to the failure contract dump so the exact
  bird ownership/removal lifecycle can be located;
- does not change bird state, timers, menus, physics, score, or rendering.
