# v0.26.53 — Stage 24.22.2 Bird Removal Settle Audit

Diagnostic-only follow-up to Stage 24.22.1.

The Level57 loss run proved that `checkLevelFailed()` is blocked by stale entries in global `birds`: shot birds can remain `controllable=true` after all five shots are consumed. The untouched `updateGame` bytecode also recovered the normal removal gate: a shot controllable bird receives/updates `isReadyForRemoveTimer`, the timer only counts down while `vLength(xVel,yVel) < 0.05`, and `removeBird(bird)` is reached after the timer expires when the camera no longer owns a target.

This stage does not change gameplay. It adds:

- untouched `removeBird` Lua bytecode to the failure-contract dump;
- per-second telemetry for every stale `controllable && shot` bird: Lua velocity, speed, angular velocity, sleeping flag, `isReadyForRemoveTimer` type/value, camera target, Box2D body velocity/awake state, and first-fixture friction/restitution/density;
- ground fixture telemetry for comparison;
- `stage24.22.2-bird-removal-settle.txt` in the diagnostic ZIP.

Do not fix the failure path by lowering the 0.05 threshold or forcing `controllable=false`. If the timer is being held at 1.0 by a non-vanilla resting velocity, the underlying settle/contact mismatch must be identified first.
