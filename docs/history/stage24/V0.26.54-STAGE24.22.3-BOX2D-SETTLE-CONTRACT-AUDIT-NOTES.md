# v0.26.54 — Stage 24.22.3 Box2D Settle Contract Audit

## Finding carried forward from 24.22.2

The level-failed deadlock is not a menu problem. Shot birds remain
`controllable=true` because the untouched Lua `updateGame()` removal gate waits
for `vLength(xVel,yVel) < 0.05` long enough for `isReadyForRemoveTimer` to
expire. In the current ARM64 physics candidate, some grounded Red birds enter a
small repeating contact cycle instead: their vertical velocity repeatedly
returns to about `+1.198`, so the timer resets to `1` forever even after
`hasMovingObjects` has become false.

The observed bird fixture is still the recovered level data:

- friction `0.30`
- restitution `0.43`
- density `6.0`

No gameplay value is changed in this stage.

## Audit goal

Before changing the Lua `0.05` gate, bird restitution, sleep state, or any
contact behavior, compare the untouched ARMv7 Box2D implementation against the
pinned public Box2D 2.1.2 candidate used by the port.

The build emits:

`stage24.22.3-box2d-settle-contract.txt`

It contains full ARMv7 bodies, when symbols are present, for the relevant
contact-solver/island/world functions and the matching pinned 2.1.2 source
sections around velocity/restitution and sleep thresholds.
