# v0.26.55 — Stage 24.22.4 Box2D Contact-Bias Contract Audit

## Proven by Stage 24.22.3

The untouched ARMv7 `b2Island::Solve` does **not** use the stock Box2D 2.1.2
sleep constants verbatim:

- ARMv7 compares linear velocity squared against `0.01`, therefore the compiled
  linear sleep tolerance is `0.1`.
- ARMv7 compares minimum sleep time against `0.25 s`.
- The angular sleep tolerance squared is `0.0012184699`, matching the stock
  2-degree angular tolerance.

Pinned public Box2D 2.1.2 instead defines linear sleep tolerance `0.01` and
`b2_timeToSleep = 0.5`.

That proves the Rovio physics build has local Box2D tuning. However, those
sleep values alone do not explain a bird repeatedly reaching about `1.198`
linear speed against the ground, because `1.198` is still well above either
sleep threshold.

## Stage 24.22.4 question

The public 2.1.2 contact solver enables restitution only when relative normal
velocity is below `-b2_velocityThreshold`, where stock
`b2_velocityThreshold = 1.0f`.

The observed stuck-bird contact arrives near `1.198`, just above that stock
threshold. Therefore this stage dumps the untouched ARMv7:

- `b2ContactSolver::b2ContactSolver(...)`
- `b2ContactSolver::InitVelocityConstraints(...)`

including decoded literal pools and soft-float compare neighborhoods, so the
exact restitution velocity-bias threshold can be proven rather than guessed.
