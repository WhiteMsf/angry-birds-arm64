# v0.26.56 — Stage 24.22.5 Body / Fixture Construction Contract Audit

## Why this stage exists

Stage 24.22.4 closes the restitution velocity-threshold hypothesis. In untouched
ARMv7 `b2ContactSolver::b2ContactSolver(...)`, the `vRel` comparison materializes
`0xbf800000` (`-1.0f`) immediately before `__aeabi_fcmplt`, matching stock Box2D
2.1.2 `b2_velocityThreshold = 1.0f` exactly.

The terminal deadlock remains real: some shot Red Birds can stay `controllable`
because their original Lua `speed < 0.05` removal timer never starts. Runtime
telemetry has observed a low-amplitude ground-contact loop around `+1.198 / -0.135`
y velocity while the bird fixture reports friction `0.3`, restitution `0.43`, and
density `6.0`.

That means the next fidelity boundary is not the contact threshold. It is the
native object-construction contract: does Rovio's original `createCircle` /
`createBox` path pass those Lua material values and body settings directly to
Box2D, or transform any of them before `CreateBody` / `CreateFixture`?

## What the audit captures

The build emits `stage24.22.5-body-fixture-contract.txt` and keeps gameplay
unchanged. The report:

- lists ARMv7 symbols related to GameLua, physics, circles, body/fixture defs,
  `CreateBody`, and `CreateFixture`;
- finds every disassembly callsite into Box2D body/fixture construction and prints
  the surrounding ARM instructions even if the higher-level wrapper is unnamed;
- dumps uniquely sized caller bodies and any named `createCircle` / `createBox`
  candidates;
- records raw file offsets of the `createCircle` / `createBox` API strings as a
  breadcrumb for stripped registration paths;
- includes the pinned Box2D 2.1.2 body/fixture defaults and creation source beside
  the original ARMv7 evidence.

## Current ARM64 assumptions under audit

The reconstructed bridge currently passes Lua `friction`, `restitution`, and
`density` directly into `b2FixtureDef`. It also sets `angularDamping = 1.0f` on
both boxes and circles. Neither field should be changed merely because it looks
suspicious; this stage exists to tie the exact original construction dataflow
back to ARMv7 first.

## Policy

Diagnostic only. No change to restitution, damping, sleep constants, body flags,
fixture material values, or the original Lua `speed < 0.05` removal gate.
