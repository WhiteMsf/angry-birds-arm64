# v0.26.57 — Stage 24.22.6 Contact Material Mixing Contract Audit

## Result that motivates this stage

Stage 24.22.5 resolved the untouched ARMv7 `GameLua::createCircle` and
`GameLua::createBox` construction dataflow. The physics-affecting values under
suspicion match the ARM64 bridge:

- density `== 0` selects static, otherwise dynamic;
- position and geometry are passed directly;
- `linearDamping = 0.0f`;
- `angularDamping = 1.0f`;
- `allowSleep = true`, `awake = true`, `active = true`;
- `fixedRotation = false`, `bullet = false`;
- `inertiaScale = 1.0f`;
- fixture friction, restitution, and density pass through directly;
- box half-extents use `width * 0.5`, `height * 0.5`; recovered polygon radius
  remains `0.1f`;
- circle radius passes directly.

The original fixture `userData` is the `RenderObjectData*`; the current bridge
uses `nullptr`. That is a fidelity mismatch to restore when native object identity
is reconstructed, but Box2D does not use fixture user data to compute contact
impulses, so it cannot explain the terminal micro-bounce.

## Why contact material mixing is next

Runtime telemetry already showed a terminal Red Bird fixture with friction `0.3`,
restitution `0.43`, density `6.0`, and ground friction `0.8`, restitution `0.0`,
density `0.0`. Stock Box2D 2.1.2 combines fixture materials as:

- friction: `sqrt(frictionA * frictionB)`;
- restitution: `max(restitutionA, restitutionB)`.

If untouched Rovio uses stock restitution mixing, bird/ground contacts retain
`0.43`. If Rovio changed the rule, the effective contact restitution could differ
without any change to either fixture definition.

## What this build does

Diagnostic only. The build emits
`stage24.22.6-contact-material-mix-contract.txt`, which inventories and disassembles
untouched ARMv7 `b2Contact` ownership functions and puts them beside the pinned
Box2D 2.1.2 contact-mixing source. It highlights soft-float compare, multiply, and
sqrt neighborhoods used to recover the exact friction/restitution combination.

No gameplay, material, contact, sleep, failure-state, score, rendering, or Lua
lifecycle behavior is changed.
