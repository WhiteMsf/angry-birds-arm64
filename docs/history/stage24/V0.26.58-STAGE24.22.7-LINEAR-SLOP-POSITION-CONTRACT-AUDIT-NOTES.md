# v0.26.58 — Stage 24.22.7 Linear Slop / Position Correction Contract Audit

## What Stage 24.22.6 actually resolved

Stage 24.22.6 inspected named `b2Contact` ownership, but Box2D 2.1.2 does not
perform material mixing there. The mix is computed while constructing
`b2ContactSolver` constraints.

Fortunately Stage 24.22.4 had already dumped that exact untouched ARMv7 region.
At `0x77ff8..0x78008`, the original loads the two fixture frictions, multiplies
them, and calls `sqrtf`. Immediately afterward it loads the two restitutions,
compares them, and keeps the greater value. Therefore the original contract is:

- friction = `sqrt(frictionA * frictionB)`;
- restitution = `max(restitutionA, restitutionB)`.

That is stock Box2D 2.1.2 behavior, so contact material mixing is closed and is
not the source of the terminal Red Bird micro-bounce.

## Stronger remaining clue

Earlier ARMv7 shape reconstruction proved that local polygon/box shape
construction materializes `m_radius = 0.1f`. Stock Box2D 2.1.2 normally defines:

- `b2_linearSlop = 0.005f`;
- `b2_polygonRadius = 2 * b2_linearSlop = 0.01f`.

The current ARM64 bridge compensates by forcing polygon `m_radius = 0.1f`, but
the rest of the pinned stock solver still compiles with `b2_linearSlop = 0.005f`.
That can create an internally inconsistent hybrid: Rovio-sized collision skins
with stock-sized position-correction tolerances.

A particularly plausible original configuration is `b2_linearSlop = 0.05f`,
because `2 * 0.05 = 0.1`, but this stage does not assume that value. It proves it
from ARMv7 before any patch.

## What this build audits

Diagnostic only. It emits:

`stage24.22.7-linear-slop-position-contract.txt`

The report disassembles untouched ARMv7 owners including:

- `b2ContactSolver::SolvePositionConstraints(float)`;
- `b2ContactSolver::b2ContactSolver(...)`;
- `b2Island::Solve(...)`;

and compares them with the pinned Box2D 2.1.2 source for:

- `b2_linearSlop`;
- `b2_polygonRadius`;
- `b2_maxLinearCorrection`;
- `b2_contactBaumgarte`;
- related position-solver constants.

It also tags known IEEE-754 candidates such as `0.005`, `0.05`, `0.1`, `0.2`,
and `0.75` in literal pools and prints soft-float math neighborhoods.

No physics, sleep, contact, failure-state, Lua lifecycle, score, rendering, or
input behavior is changed.
