# v0.26.59 — Stage 24.22.8 — Rovio Box2D tolerance restore

## Why this stage exists

A failed Level57/1-2 run proved that stale shot birds can remain `controllable=true`
forever because their ground-contact motion never falls below the untouched Lua
`speed < 0.05` removal gate. Stage24.22.2 measured a persistent low-amplitude
contact loop; Stages24.22.3..24.22.7 then audited the original ARMv7 Box2D owner
before changing any gameplay logic.

Stage24.22.7 closes the missing tolerance-scale contract directly from
`b2ContactSolver::SolvePositionConstraints(float)` and `b2Island::Solve`:

- `b2_linearSlop = 0.05f` (ARMv7 literal `0x3d4ccccd` in the exact
  `separation + linearSlop` path);
- `b2_polygonRadius = 2 * linearSlop = 0.1f`, consistent with the independently
  recovered GameLua polygon/box `m_radius = 0.1f`;
- `b2_timeToSleep = 0.25f`;
- `b2_linearSleepTolerance = 0.1f` (the island compares squared linear speed
  against `0.01f`);
- `b2_angularSleepTolerance` remains stock (ARMv7 squared literal matches
  `(2 deg in radians)^2`);
- `b2_velocityThreshold = 1.0f` remains stock;
- `b2_maxLinearCorrection = 0.2f` remains stock;
- `b2_contactBaumgarte = 0.2f` remains stock.

The strongest Stage24.22.7 signature is the complete position-correction trio:
`+0.05`, clamp at `-0.2`, and success threshold `-0.075`, where
`-0.075 = -1.5 * 0.05`. This is the stock 2.1.2 algorithm with Rovio's larger
linear slop, not a guessed gameplay fix.

## Implementation

The build still downloads and SHA-verifies the same pinned Box2D 2.1.2 archive.
All diagnostic comparisons run against that pristine extracted tree first.
Only then `tools/patch_box2d212_rovio_tolerances.py` changes the three proven
non-stock settings before compilation:

- `0.005f -> 0.05f` for `b2_linearSlop`;
- `0.5f -> 0.25f` for `b2_timeToSleep`;
- `0.01f -> 0.1f` for `b2_linearSleepTolerance`.

The `b2_polygonRadius` macro remains the upstream expression
`2.0f * b2_linearSlop`, so it now naturally evaluates to the recovered `0.1f`.
No restitution, friction, density, damping, contact mixing, Lua failure logic,
Lua `speed < 0.05` gate, or score/render behavior is modified.

## Validation target

Run the failed-level scenario again in 1-2. The primary pass condition is not
"force the fail menu": it is that resting shot birds converge under the restored
Rovio solver tolerances, the original Lua removal timer is allowed to count down,
and `checkLevelFailed()` can become true without any synthetic fail trigger.

The build emits `stage24.22.8-rovio-box2d-tolerances.txt` and the device runtime
emits `[stage24.22.8-rovio-physics] ...` with the compiled constants.
