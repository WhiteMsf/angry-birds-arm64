# v0.26.6 — Stage 24.3 persistence root + original initializeMenu bootstrap probe

This revision follows the first fully traced live Level1 completion on v0.26.5.

## Evidence driving this change

v0.26.5 recovered the original ARMv7 motion gates. On the device the runtime
changed from `moving=yes` to `moving=no` and the untouched Lua set
`levelCompleted=true`. The next post-completion fault was:

```
attempt to index global 'highscores' (a nil value)
```

The stripped Lua VM trace placed the fault inside `updateLevelEnding()`.
Static decoding of the original 1.4.2 `gamelogic.lua` confirms that
`updateLevelEnding()` expects the top-level `highscores` table to have already
been loaded by the application persistence bootstrap. It creates the per-level
entry (`highscores[levelName]`) itself on a clean profile.

## What v0.26.6 changes

- Creates only the proven missing persistence root: `highscores = highscores or {}`.
- Preserves the untouched original `initializeMenu()` Lua closure before the
  historical headless replacement is installed.
- After `initialize()` returns, calls the preserved original `initializeMenu()`
  under exact-PC tracing.
- A failure in this menu-only bootstrap is logged but does not regress the
  already-proven live Level1 gameplay path. Transient menu-dispatch globals are
  cleared before continuing.
- Logs whether the original menu bootstrap succeeded and whether original
  `levelComplete.items` / `levelFailed.items` tables were constructed.
- After completion, logs `currentMenuPage`, `newMenuPage`, result item count and
  highscores root state.
- Keeps the post-completion quarantine so the first remaining boundary is
  observable without losing the EGL Surface.

## What this does NOT claim

- No real highscores/settings file persistence yet (`saveLuaFile` is still a
  compatibility stub in this stage).
- No result/menu sprite renderer yet. The live renderer still draws the recovered
  game-object GLES1 passes only.
- `prepareMenuPage` remains a stub, so native menu layout preparation is still an
  open reverse-engineering boundary.
- The goal of this revision is to get the original result-state machine past the
  persistence bootstrap and identify/construct the real page data before adding
  the original UI atlas renderer.
