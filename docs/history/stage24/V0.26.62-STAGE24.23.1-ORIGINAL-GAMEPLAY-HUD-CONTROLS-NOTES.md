# v0.26.62 — Stage 24.23.1 — original gameplay HUD controls

Stage24.23.0 audited the untouched Angry Birds 1.4.2 `drawGame`,
`updateGame`, and `createMenuPages` closures before the native bridge replaces
resource/input calls.  This stage materializes only the HUD behavior that the
audit proves.

## HUD arrow

Untouched `drawGame` pc=0223..0268:

- requires `useLevelLimits`;
- requires a non-nil `cameraTargetObject`;
- draws only when `cameraTargetObject.y * physicsToWorld < screen.top`;
- uses `setRenderState(-screen.left, -screen.top, A8, A8, 0,
  cameraTargetObject.spritePivotX, cameraTargetObject.spritePivotY)`;
- `A8` is the drawGame world scale local initialized from `worldScale` and
  replaced by `tempWorldScale` when present;
- draws `INGAME_BIRDS_1 / HUD_ARROW_UP` at
  `floor(cameraTargetObject.x * physicsToWorld), floor(screen.top)`;
- original sprite metadata recovered by Stage24.23.0 is rect
  `730,336 13x10`, pivot `6,-2`.

The reconstructed renderer executes this immediately after the front
slingshot, matching the untouched draw order, and before the fixed score HUD.

## Gameplay menu button

Untouched `drawGame` pc=0627..0671:

- restores `fontBasic` after floating scores;
- uses the ordinary Android identity render-state branch (the 2x branch is an
  iPhone4-only resolution special case);
- draws `BUTTONS_SHEET_1 / MENU_BUTTON` at `(0,0)`;
- the four-argument `res.drawSprite` call supplies no explicit anchors, so the
  original SPRT pivot semantics own placement;
- resets render state to identity immediately afterward.

The button is therefore not reconstructed from screenshots or from the pause
menu's separate `BUTTON_MENU` sprite.

## Input ownership

Untouched `createMenuPages` pc=2517..2535 calls
`res.getSpriteBounds("BUTTONS_SHEET_1", "MENU_BUTTON")` and stores the result
as `pauseButtonW` / `pauseButtonH`.  The audited Android runtime produced
`73 x 71`; only the original iPhone4 branch multiplies these dimensions by
`1.7`.

Untouched `updateGame` pc=0471..0495 already owns input: on an LBUTTON press it
checks `cursor.x < pauseButtonW` and `cursor.y < pauseButtonH`, then calls
`goToMenu()` outside the editor.  Stage24.23.1 adds no native hitbox and no
synthetic pause/menu transition; it only restores the missing visual sprite.

## HUD block gate

The complete Stage24.23.0 dump also proves `drawGame` pc=0269..0311 skips the
fixed score/floating-score/MENU_BUTTON block while `currentGameMode ==
updateEditor`, and while `currentGameMode == updateMenu` on any of:

- `levelComplete`
- `levelFailed`
- `gameFinished`
- `gameFinishedThreeStars`
- `gameFinishedLP2`
- `gameFinishedThreeStarsLP2`

Stage24.23.1 applies that recovered gate consistently to the already-restored
score and floating-score paths plus the new menu button.  `HUD_ARROW_UP` is
before this gate in untouched drawGame and stays there.

## Expected runtime test

On the default 854x480 WVGA debug presentation, `MENU_BUTTON` should be visible
at the upper-left immediately during gameplay.  Tapping it should be consumed
by the untouched Lua `updateGame` path and transition through `goToMenu()`.
`HUD_ARROW_UP` is conditional and does not need to be forced for the primary
smoke test.

`pull-stage24-live-log.ps1` writes `stage24.23.1-gameplay-hud.txt` with exact
sprite metadata, runtime hitbox dimensions, and first arrow draw when that
branch occurs.
