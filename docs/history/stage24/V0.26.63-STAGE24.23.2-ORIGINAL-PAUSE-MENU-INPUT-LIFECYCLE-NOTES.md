# v0.26.63 — Stage 24.23.2 — original pause-menu input lifecycle

Stage24.23.1 restored the exact `BUTTONS_SHEET_1 / MENU_BUTTON` pixels, but its
first live validation exposed an older Stage8 headless bootstrap still forcing
`pauseButtonW = pauseButtonH = -1000000000` *after* original `initializeMenu()`
had already produced the correct `73 x 71` Android bounds. The screenshot
therefore showed the right button while touches inside it could not reach
untouched `updateGame()`'s original guard.

This stage removes only that obsolete headless override. It does not create a
native touch region: `createMenuPages()` still owns the bounds and untouched
`updateGame()` still checks LBUTTON/cursor against them and calls `goToMenu()`.

Once Lua selects `currentGameMode=updateMenu` and `currentMenuPage=pause`, the
existing generic GLES1 bridge now passes that page through the same untouched
`drawMenu()` closure already used for `levelComplete` and `levelFailed`. No
pause-page coordinates, sprites, labels, transitions, or actions are recreated
by hand.

Expected smoke test: launch Level1, tap the visible top-left pause button, and
verify the original pause menu appears. The diagnostic bundle adds
`stage24.23.2-pause-menu.txt`; a PASS should report a 73x71 hitbox and the first
visible `pause` drawMenu frame.
