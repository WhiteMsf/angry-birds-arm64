# v0.26.64 — Stage 24.23.3 — FONT_MENU texture transport

The Stage24.23.2 live run proved the original pause-button input path is already
working. A touch at logical `(35.70, 41.13)` inside the recovered `73 x 71`
`MENU_BUTTON` changed `currentGameMode` from `updateGame` to `showPauseMenu` on
the next frame.

The game thread then exited during the first pause-menu draw because untouched
`drawMenu()` selected `FONT_MENU`, while the APK texture transport set still
contained only `FONT_BASIC`, `FONT_BIG_NUMBERS`, and `FONT_SCORE`. The font DAT
itself had loaded correctly and identified the exact original image as
`FONT_MENU_N900.pvr` (89 glyphs, leading 45); only the image transport was
missing.

This stage adds `FONT_MENU.dat` to the same DAT-driven texture staging pipeline.
The image filename is recovered from the untouched DAT header and the original
PVR bytes are transported exactly like the already-working bitmap fonts. No
pause-menu coordinates, hitboxes, labels, transitions, button actions, or font
metrics are synthesized.

Expected smoke test: launch Level1, tap the top-left pause button once, and
verify the original pause page becomes visible instead of the native game thread
exiting. Existing `stage24.23.2-pause-menu.txt` telemetry should then report the
first visible pause drawMenu frame and the surviving 73x71 original hitbox.
