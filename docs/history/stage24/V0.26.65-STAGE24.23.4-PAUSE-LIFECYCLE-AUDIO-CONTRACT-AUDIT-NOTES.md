# v0.26.65 — Stage 24.23.4 — Pause lifecycle / audio contract audit

Diagnostic-only follow-up to Stage24.23.3.

The Stage24.23.3 runtime test proved the pause page renders with the original
FONT_MENU and that original menu actions receive touch. It also exposed two
remaining boundaries:

- BUTTON_RESUME changes `currentGameMode` from `updateMenu` to the untouched
  `hidePauseMenu`, but on the next frame the original state returns to
  `updateMenu` instead of resuming gameplay.
- BUTTON_RESTART works through the untouched menu action and reaches
  `updateLoading` / reloads Level1.
- BUTTON_SFX reaches untouched `drawMenu` pc 411 and fails because the Stage24
  resource bridge has no `res.getTrackVolume` member yet.

This stage does **not** patch any of those behaviors. It dumps the complete
untouched Lua Protos for `goToMenu`, `showPauseMenu`, `hidePauseMenu`,
`gameResumed`, `updateMenu`, `drawMenu`, and `setGameMode`, inventories the
current `res` audio members, and statically disassembles the original ARMv7
`game::LuaResources::{get,set}TrackVolume` plus master-volume/audio context.

Goal: recover ownership/dataflow before adding the missing native volume bridge
or touching pause/resume state.
