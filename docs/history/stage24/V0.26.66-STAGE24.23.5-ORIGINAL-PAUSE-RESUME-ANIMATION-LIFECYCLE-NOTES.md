# v0.26.66 — Stage 24.23.5 original pause/resume animation lifecycle

## Evidence from v0.26.65

The untouched `hidePauseMenu()` does not resume gameplay immediately. It calls:

1. `setAnimationState("ingamePausePageScroll", "EXITING")`
2. `setGameMode(updateMenu)`
3. `drawMenu()`

The Stage 8 headless harness had later replaced `setAnimationState` with `l_noop` because no pause UI existed at that time. With the visual pause menu restored, this legacy stub prevented the original animation state machine from ever progressing the EXITING transition.

The same untouched initialization path creates `ingamePausePageScroll` through `newAnimation(..., "HIDDEN", pausePage, 600, 600)`, while untouched `updateMenu()` calls the normal animation/update path.

## Change

- Removed only the historical `setAnimationState -> l_noop` replacement from the live Stage24 boundary.
- Preserves untouched `setAnimationState` and `updateAnimations` Lua closures.
- Adds a startup invariant that both are original Lua closures; boot fails instead of silently substituting guessed pause behavior if either owner is missing.
- No synthetic resume action, no forced `setGameMode(updateGame)`, no forced `setPhysicsEnabled(true)`, and no animation timing constants were added.
- Audio volume methods remain intentionally out of scope here; v0.26.65 proved their native API but the actual audio backend is still a later fidelity stage.

Expected result: `BUTTON_RESUME` drives the original EXITING animation and returns to gameplay through the original animation/menu lifecycle.
