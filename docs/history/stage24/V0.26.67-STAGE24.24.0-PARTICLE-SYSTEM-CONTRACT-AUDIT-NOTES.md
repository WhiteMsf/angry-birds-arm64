# v0.26.67 — Stage 24.24.0 particle-system contract audit

## Why this stage

Stage 24.23.5 closed the visible gameplay HUD / pause-resume lifecycle. The
next missing gameplay system is particles. Particles have deliberately remained
headless since Stage 13/16: untouched Lua chooses particle types and spawn
parameters, while `_G.particles.addParticles(...)` is a native no-op boundary.

This stage is diagnostic-only. It does **not** render, update, scale, fade,
randomize, or simulate particles yet.

## Runtime Lua audit

Before native bindings replace any original names, the runtime now dumps:

- every entry under `particleTable.particles` (19 definitions in the recovered
  1.4.2 corpus), including nested scalar/string/table fields;
- the complete untouched `newParticles` and `addParticles` Lua bytecode;
- particle-related windows from `birdCollision`, `blockCollision`,
  `removeBird`, `removeBlocks`, and `updateGame`.

The existing headless `particles.addParticles` call trace is preserved so a
normal gameplay run can correlate real producers such as `redBuff`,
`woodenBuff`, and `smokeBuff` with their recovered definitions.

## Original ARMv7 native audit

The build also inventories the original `libangrybirds.so` for:

- `Particles::...` wrapper symbols;
- retained `ParticleSystem` / `ParticleView` symbols;
- disassembly of the Angry Birds particle-wrapper methods when symbols are
  available;
- particle-related native strings (`MaxParticles`, lifetime/start/end fields,
  emitter/sprite terminology, etc.).

This is intended to establish the native interpretation/update/render contract
before replacing the headless boundary.

## Policy

No guessed emitter behavior, no screenshot-derived velocities, no hand-made
fade curve, and no magic particle counts. Stage 24.24.0 only collects ownership
and dataflow evidence.
