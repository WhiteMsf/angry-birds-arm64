# v0.26.68 — Stage 24.24.1 exact particle emitter/limit + HUD alpha provenance audit

## Why this stage

Stage 24.24.0 recovered the original 1.4.2 custom `Particles` wrapper, all 19
untouched Lua definitions, the native 8-argument spawn boundary, the 108-byte
`ParticleData` array, and the native update/draw owners. Before replacing the
long-standing headless particle bridge, this stage closes the last emitter and
limit-policy details and fixes a historical telemetry-label error.

The user also noticed that the recovered top-left gameplay `MENU_BUTTON` looks
washed out. Stage 24.23.1 already proves that untouched `drawGame` uses the
ordinary Android identity render state for that draw, while the ARM64 sprite
bridge explicitly submits `glColor4f(1,1,1,1)`. Stage 24.24.1 therefore audits
the original source texels before changing alpha/blend state or substituting a
sprite.

## Particle spawn telemetry correction

The Stage16 headless trace historically labeled arguments 2 and 3 as `x` and
`y`. Stage 24.24.0 proves the real native signature is:

```
particles.addParticles(type, count, x, y, width, height, angle, bypassLimits)
```

The boundary remains a no-op in v0.26.68, but it now logs all eight arguments
with those proven meanings under `stage24.24.1-particle-spawn`.

## Exact ARMv7 emitter / limit audit

The new static report targets the original `Particles::Particles`,
`Particles::addParticles`, and `Particles::update` implementations and refuses
to emit the semantic PASS if the expected native dataflow markers disappear.
Recovered contract:

- default soft factor = `0.5`;
- default soft limit = `40` active particles;
- default hard limit = `125` active particles;
- unless argument 8 bypasses limits, a spawn that crosses the soft limit first
  scales its requested count by 0.5, then the hard limit clamps the count to
  remaining capacity;
- the native loop compares integer emitted-count converted to float against the
  adjusted requested count, so a positive non-integral request emits
  `ceil(count)` particles;
- `randomizeBirthPosition` defaults true when absent;
- randomized birth position is uniform over the supplied emitter rectangle and
  rotated by the supplied object angle before translation;
- X and Y velocity components are independently uniform over `minVel..maxVel`;
- start/end scale and angular velocity are independently uniform over their Lua
  min/max fields;
- particle initial draw angle comes from `angleMinEmitter..angleMaxEmitter`,
  converted from degrees to the radian angle consumed by native `sin/cos`;
- `animation == "lifeTime"` selects lifetime-driven sprite sequencing;
- update integrates age, gravity, velocity, position, angle and linear scale;
  animated sprite index is `ceil(spriteCount * age/lifetime)` clamped to the
  valid range;
- the custom wrapper has no separate alpha-fade curve.

No particle simulation or rendering is enabled in this stage.

## MENU_BUTTON raw-alpha provenance

On the first gameplay HUD draw, the renderer audits exact level-0 RGBA4444
texels for `MENU_BUTTON` and comparison controls from the same original
`BUTTONS_SHEET_1.pvr`. It reports the 16-bin alpha histogram, transparent /
partial / full-alpha counts, mean non-zero alpha, and RGB means. The source PVR
contract already requires masks `R=f000 G=0f00 B=00f0 A=000f`, matching the
live `GL_RGBA + GL_UNSIGNED_SHORT_4_4_4_4` upload.

This is diagnostic only: no button opacity, blend mode, sprite selection,
position, scale or input behavior changes.
