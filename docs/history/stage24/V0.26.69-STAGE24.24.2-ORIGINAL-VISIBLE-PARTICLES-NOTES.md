# v0.26.69 — Stage 24.24.2 original visible gameplay particles

This stage materializes the custom `Particles` wrapper recovered from the untouched
ARMv7 binary. The Lua producer boundary remains original: `newParticles()` calls
`particles.addParticles(type,count,x,y,width,height,angle,bypassLimits)`, and all
particle definitions remain owned by untouched `particles.lua`.

Recovered runtime contract implemented:

- soft limit 40, soft factor 0.5, hard limit 125; arg8 bypasses both adjustments;
- positive fractional adjusted counts create `ceil(count)` particles, matching the ARM loop;
- birth positions are randomized in the emitter rectangle then rotated by emitter angle;
- X/Y velocity, angular velocity, start/end scale and non-animated sprite choice use the native random domain;
- `animation=lifeTime` starts at sprite 1 and advances by `ceil(spriteCount*age/lifeTime)`;
- age, gravity, position, angle and scale update follow the recovered `Particles::update(float)` arithmetic;
- removal is strict `age > lifeTime`;
- there is no synthetic alpha/fade curve;
- draw order is the exact `GameLua::drawGame()` boundary after native object passes and before foreground;
- all particle sprites resolve through `INGAME_BIRDS_1` metadata and the untouched atlas.

## HUD alpha side finding

The Stage24.24.1 raw RGBA4444 audit proved `MENU_BUTTON` is intentionally washed
out in the original asset: its sprite rectangle has no alpha=15 texels, with most
visible pixels around the middle alpha levels. The renderer already submits white
modulation at alpha 1, so no compatibility correction is warranted.
