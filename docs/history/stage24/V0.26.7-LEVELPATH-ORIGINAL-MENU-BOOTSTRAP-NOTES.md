# v0.26.7 — Stage 24.4 levelPath + original menu bootstrap

## Evidence from v0.26.6

- `initializeMenu()` reached original `createMenuPages()` and failed at PC 496:
  `attempt to concatenate global 'levelPath' (a nil value)`.
- Gameplay remained intact and Level1 reached `completed=yes`.
- `highscores` changed from 0 entries to 1 before the later post-complete fault,
  proving the v0.26.6 persistence-root bootstrap allowed original
  `updateLevelEnding()` to create the Level1 score record.
- The later `levelComplete == nil` fault is a consequence of the earlier menu
  construction failure, not a new gameplay-core regression.

## Bytecode boundary recovered

The stripped `gamelogic.lua` instruction at `createMenuPages` PC 496 is the
`CONCAT` for the logical expression:

    levelPath .. "/pack" .. worldNumber .. "/"

The original APK asset tree stores levels under `data/levels/packN/`, therefore
Stage 24.4 restores only:

    levelPath = "data/levels"

This is a resource-layout-derived bridge.  It is deliberately not labeled as
an independently recovered ARMv7 native string literal yet.

## Scope

No gameplay physics, gravity, motion gates, touch, camera, interpolation,
draw-order, damage, or GLES state changes. No visual menu/result renderer is
added yet. No guesses are made for `imagePath`, `audioPath`, `fontPath`, or
`localizationPath`; if the original menu bootstrap reaches one of those and
fails, the exact tracing path remains active and will identify it.
