# v0.26.71 / Stage 24.25.1 — Audio mixer + original WAV contract audit

Diagnostic-only continuation of Stage 24.25.0.

Stage 24.25.0 proved the untouched Lua/ARMv7 surface:

- `res.playAudio(name, volume=1.0, loop=false, track=0)` returns a numeric playback handle.
- `res.isAudioPlaying(...)` accepts either that numeric handle or a clip name.
- `stopAudio(name)` resolves the named AudioClip and stops it.
- `stopAllAudio()` delegates to AudioOutput::stopClips().
- track/master volume are owned by AudioOutput/AudioMixer.

This stage does **not** play sound yet. It tightens the last backend questions before implementation:

1. Disassemble `audio::AudioOutput::playClip/stopClip/stopClips/isClipPlaying`, the relevant `audio::AudioMixer` methods, `AudioClip` construction, and output construction.
2. Parse every untouched local `assets/data/sfx/*.wav` RIFF header and report exact codec/channels/sample-rate/bit-depth/block-align/byte-rate/data-size/duration groups.
3. Replace the historical silent `playAudio` no-op with a diagnostic boundary that logs the exact runtime name/volume/loop/track selected by untouched Lua, but returns `-1` (the original missing-clip sentinel) and remains headless.
4. Report whether `audioGroups` exists in the live runtime. This matters because Stage24 bypasses the original splash/createAssets path; if the table is absent, the next implementation stage must restore the original audio-registration/group slice rather than guessing aliases.

No WAV bytes are redistributed in this bootstrap package and no original asset is modified.
