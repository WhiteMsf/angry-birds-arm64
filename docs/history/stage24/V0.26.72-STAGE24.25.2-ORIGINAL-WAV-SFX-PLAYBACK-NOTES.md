# v0.26.72 / Stage 24.25.2 — Original WAV SFX playback

## Evidence carried forward

The Stage24.25.1a diagnostic run found the untouched audio tree at `assets/data/audio`, not at the earlier assumed `assets/data/sfx` path.

The original payload inventory contains 168 WAV files. Every one is RIFF PCM format 1 at 16 kHz / signed 16-bit; 167 are mono and `ball_bounce.wav` is stereo. The untouched `createAssets()` bytecode contains 184 `res.createAudio(...)` calls: 166 WAV registrations and 18 MP3 registrations. Two WAV payloads therefore exist in the tree without being registered by that closure. This stage does not manufacture aliases for either case.

Stage24.25.0/25.1 also proved the Lua/native contract used here:

- `res.createAudio(path, alias)` registers a clip alias.
- `res.playAudio(name [, volume [, loop [, track]]])` returns a numeric handle, defaulting to volume 1, loop false, track 0.
- missing/unavailable clips return `-1`.
- `res.isAudioPlaying(...)` accepts either a numeric handle or an alias.
- `stopAudio`, `stopAllAudio`, track volume, master volume, start/stop output are native resource/audio-output services.

## What changed

1. Packages the user's own untouched `assets/data/audio` subtree into the locally built APK at `assets/stage24/data/audio`. The project archive itself does **not** contain Rovio audio payloads.
2. Replays the untouched 1.4.2 `createAssets()` closure inside an isolated Lua environment. Only the already-restored composprite/font prefix functions are neutralized. Original bytecode therefore performs all 184 `createAudio` calls and constructs `audioGroups`; no alias or group table is handwritten.
3. Copies the resulting original `audioGroups` and `currentMainMenuSong` back into the live game environment.
4. Implements the proven WAV side with a small OpenSL ES software PCM mixer:
   - 16 kHz stereo output;
   - signed 16-bit samples;
   - original mono clips duplicated L/R, original stereo clip preserved;
   - per-call gain × track gain × master gain;
   - looping, numeric handles, name/handle playing queries, stop by alias and stop-all.
5. Implements the recovered track/master-volume and start/stop-output resource surface, allowing the original pause SFX control to reach a real backend instead of a missing function.
6. Adds lifecycle cleanup for the OpenSL player/mixer/engine so a NativeActivity window restart does not retain stale voices or handles.
7. Adds `stage24.25.2-audio-playback.txt` to the diagnostic bundle.

## Deliberate boundary

MP3 playback is **not** implemented in Stage24.25.2. The 18 original MP3 registrations are preserved as registered-but-unsupported clips and `playAudio` returns the original missing/unavailable sentinel `-1` for them. This means music, ambient loops, level-start/complete MP3 cues, and similar long cues remain silent for this stage. Their repeated requests are left behaviorally visible; diagnostic logging is throttled only to avoid gigantic stdout files.

This is therefore the first **WAV SFX** playback stage, not completion of the whole audio subsystem.

## Acceptance test

Build/install, open 1-1, then exercise several original WAV producers: select/launch Red, hit wood/ice/stone, and hit or kill a pig. Audible output should correspond to the original aliases chosen by untouched `getAudioName()`/`audioGroups`. Opening pause and toggling SFX is also useful now that track-volume access exists.

Expected diagnostic invariants include:

- `stage24.25.2-audio-register PASS`
- `createCalls=184`
- `wavLoaded=166`
- `unsupported=18`
- nonzero original audio-group count
- first supported SFX produces `stage24.25.2-audio-backend PASS`
- supported WAV requests log `PLAY ... handle=...`
- MP3 requests log `MISS ... reason=unsupported-non-wav`

Do not call the entire audio subsystem closed until MP3/music ownership, decoding/playback, and live volume/lifecycle behavior have also been validated.
