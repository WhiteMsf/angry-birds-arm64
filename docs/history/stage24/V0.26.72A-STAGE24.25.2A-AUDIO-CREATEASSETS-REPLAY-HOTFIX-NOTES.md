# v0.26.72a / Stage 24.25.2a — createAssets audio replay hotfix

The first Stage 24.25.2 playtest was silent because the isolated untouched `createAssets()` replay failed before the first `res.createAudio()` call.

Runtime proof from the diagnostic bundle:

- `stage24.25.2-audio-register FAIL createCalls=0 wavLoaded=0 unsupported=0 groups=0`
- `error-detail='?:0: attempt to call field 'createSpriteSheet' (a nil value)'`

The untouched `createAssets()` begins with `loadImages(...)`, then `loadCompoSprites(...)`, `loadFonts()`, `setFont(...)`, and only then reaches the audio registration tail. Stage 24.25.2 neutralized the composprite/font prefix but accidentally left `loadImages()` live inside the isolated environment. That closure called `res.createSpriteSheet()`, which is intentionally absent from the audio-only `res` table, aborting the replay at zero audio registrations.

This hotfix changes only the isolation harness: `loadImages` is now neutralized alongside the other already-replayed asset-prefix functions. No audio aliases, groups, file names, or gameplay sound calls are hand-authored.

Expected proof on device:

- `stage24.25.2-audio-register PASS`
- `createCalls=184`
- supported WAV clips loaded from the original local asset tree
- original `audioGroups` copied out of the untouched replay environment
- supported gameplay SFX produce `stage24.25.2-audio-play PLAY ...`

Do not use the pause-menu SFX toggle for this validation pass. The previous test exposed a separate volume-animation/lifecycle anomaly after toggling it; that path should be audited independently instead of being patched speculatively.
