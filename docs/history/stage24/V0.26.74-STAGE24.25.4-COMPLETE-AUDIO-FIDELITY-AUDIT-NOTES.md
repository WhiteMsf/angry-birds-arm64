# v0.26.74 — Stage 24.25.4 Complete Audio Fidelity Audit

Purpose: audit the remaining audio questions before implementing MP3/music or
changing the pause SFX toggle behavior.

## Why this stage exists

Stage24.25.2a proved WAV SFX playback works. Earlier pause testing showed
track-volume values apparently growing far above 1.0, but that observation was
made through our replacement mixer. The untouched ARMv7 `AudioMixer::setTrackVolume`
body already proves the original engine clamps the requested volume into
`[0,1]` before storing it. Therefore two facts must be separated:

- untouched Lua may intentionally request an overshooting value;
- vanilla observable/stored track volume cannot exceed 1.0.

This build logs both values and mirrors only that already-proven native clamp so
subsequent `getTrackVolume()` feedback matches the original engine during the
audit.

## Audit coverage

- recursive untouched Lua proto inventory for `createMenuPages`, `updateMenu`,
  `drawMenuPage`, `prepareMenuPage`, `updateMenuPage`, `createAssets`, gameplay
  audio owners, and nested callback closures;
- every `setTrackVolume` raw Lua request vs native-clamped stored value, with
  current game mode, menu page, `settings.audioEnabled`, and exact VM callsite;
- sampled `getTrackVolume` calls with the same context;
- untouched ARMv7 `LuaResources -> Resources -> AudioOutput -> AudioMixer`
  volume path, including machine-readable clamp proof;
- original `createAudio`, `AudioClip`, `AudioReader` and MP3/MPEG-related native
  symbols/bodies when present;
- all original MP3 payload headers (MPEG version, Layer III bitrate/sample rate,
  channels, ID3 presence) without redistributing Rovio audio.

## Explicit non-goals

- no MP3 playback implementation yet;
- no hand-authored SFX button callback;
- no synthetic audio toggle state;
- no guessed music routing or decoder selection.
