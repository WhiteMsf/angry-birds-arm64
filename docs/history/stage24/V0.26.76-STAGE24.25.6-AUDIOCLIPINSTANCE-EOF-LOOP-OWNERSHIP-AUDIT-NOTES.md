# v0.26.76 — Stage 24.25.6 AudioClipInstance EOF / Loop Ownership Audit

## Audio-ramp conclusion from Stage24.25.5

The clean level-complete run starts with both `audioRampVolume` and
`audioRampLength` nil, reaches `updateMenu` on the completed level, and emits no
runtime ramp writer and no post-bootstrap track-volume write.

The exhaustive untouched-Lua Proto scan found only these writers:

- `changeAudio`: initializes `audioRampVolume` from track 7 and sets
  `audioRampLength` to `-0.5` when muting or `+0.5` when enabling.
- `updateMenu`: advances `audioRampVolume += dt/audioRampLength`; it clears the
  ramp only on the `audioRampVolume <= 0` branch.
- `updateSoundboard`: contains the equivalent ramp update/clear pattern.

Therefore a positive ramp created by re-enabling SFX has no Lua `>=1` stop.
If gameplay resumes, `updateMenu` stops executing but the positive ramp globals
remain live. When a later terminal menu resumes `updateMenu`, the same original
ramp continues increasing. The untouched ARMv7 mixer is the intended saturation
boundary because `setTrackVolume` clamps stored values to `[0,1]`.

No compatibility clamp is added to Lua.

## Why one more MP3 ownership audit is required

Stage24.25.5 proved:

`AudioMixer::mixUnlimited* -> AudioClipInstance::fetchData -> AudioClip::getData
-> AudioReader::readData -> AudioReader::readData_mp3`

The previous report dumped every function in that chain except
`AudioClipInstance::fetchData`, which is exactly where EOF, cursor rewind and the
per-instance loop flag can be consumed. Implementing MP3 before dumping that
body would still require guessing lifecycle behavior.

Stage24.25.6 therefore disassembles:

- all `AudioClipInstance::*` symbols, especially `fetchData`;
- all `AudioClipCursor::*` symbols;
- `AudioMixer::flushQueueAndRemoveEndedClips`;
- relevant stop/query/count methods;
- the surrounding play/mix/getData/readData functions.

Primary report:

`stage24.25.6-audioclipinstance-eof-loop-contract.txt`

This revision is diagnostic only. WAV playback and the proven ARMv7 track-volume
clamp remain unchanged; MP3 playback is still gated.
