# v0.26.78 — Stage 24.25.8 — audio lifecycle closure audit

## Evidence from the v0.26.77 live run

The Stage24.25.7 diagnostic bundle proves the MP3 path is alive end-to-end:

- untouched `createAssets()` replay registers 184 clips: 166 WAV + 18 MP3, with 27 original `audioGroups`;
- `level start military a1` decodes from original `audio/mpeg` to 56,120 mono PCM frames at 16 kHz and is played as a non-loop voice;
- `ambient_theme1` decodes to 444,043 mono PCM frames (about 27.75 s) and is played with `loop=true`, track 7;
- `level clear military a2` decodes to 85,240 frames and is played as a non-loop voice;
- the OpenSL queue is `PLAYING`, callbacks continue through at least callback 609, every observed callback is non-zero, and native stderr is empty.

The same run also exposes one unresolved fidelity question: Lua repeatedly requests `ground_collision`, but the restored registry returns the original missing-clip sentinel `-1`. That may be a genuine 1.4.2 no-op rather than a missing port asset, so this stage audits it instead of mapping it to an arbitrary sound.

## What Stage 24.25.8 changes

No intended audio behavior changes from v0.26.77. This stage adds only evidence:

- every natural non-loop voice EOF logs `END` with handle, alias, clip kind, frame count, track and volume;
- every loop rewind logs `LOOP_WRAP`; the decisive validation is `ambient_theme1` wrapping after its first ~27.75 s cursor;
- `isAudioPlaying`, `stopAudio`, `stopAllAudio`, `startAudioOutput` and `stopAudioOutput` calls gain bounded lifecycle telemetry;
- the entire original `audioGroups` table is dumped once after untouched `createAssets()` replay;
- `ground_collision` misses record Lua callsite/PC, registry presence and `audioGroups` membership;
- build-time `stage24.25.8-audio-closure-contract.txt` disassembles relevant untouched ARMv7 AudioOutput/AudioMixer/Resources functions and scans the user's untouched scripts/audio tree for `ground_collision` provenance.

The existing MP3 compatibility decoder remains Android MediaExtractor/MediaCodec. The original ARMv7 executable used mpg123; decoder internals are therefore still a documented compatibility boundary, while observable Lua/mixer lifetime, loop, track and handle ownership remain reconstructed from the original binary.
