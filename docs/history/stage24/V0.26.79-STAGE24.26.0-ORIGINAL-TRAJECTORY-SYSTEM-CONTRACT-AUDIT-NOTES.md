# v0.26.79 — Stage 24.26.0 Original Trajectory System Contract Audit

## Purpose

Stage 24.25.8 closes the observable audio lifecycle. The next live gameplay boundary that is still headless is the original trajectory API: the previous run exercised `addToTrajectory` 41 times and `startNewTrajectory` once while the generic bridge still returned no-op. `addPuffToTrajectory` did not fire on that Level 1-1 path.

This revision is deliberately **diagnostic-only**. It does not draw the familiar dotted trail and it does not guess storage, spacing, lifetime, clearing, point limits, puff behavior, or sprite choice.

## What changed

### Runtime Lua / binding audit

The live bridge now inspects the untouched loaded Lua Proto trees before replacing native bindings and records ownership windows around:

- `startNewTrajectory`
- `addToTrajectory`
- `addPuffToTrajectory`
- `birdTrajectory`
- `recordTrajectory`
- `allowTrajectoryClearing`

The three trajectory bindings are then replaced by dedicated **headless diagnostic no-ops**. They preserve the previous observable return behavior while logging:

- exact `argc`;
- raw `arg1`, `x`, and `y` values without assigning semantics to `arg1`;
- point-to-point `dx`, `dy`, and distance when consecutive calls belong to the same raw `arg1` stream;
- total and per-generation ADD/PUFF counts;
- bounding box for points seen since the previous `startNewTrajectory`;
- current native frame and Lua frame;
- `currentGameMode`, bird state, `recordTrajectory`, `allowTrajectoryClearing`, and `birdTrajectory` length;
- exact last-observed Lua Proto/callsite PC.

A `startNewTrajectory` call emits a summary of the preceding run before opening the next audit generation. Nothing is stored for rendering or fed back into game state.

### Original ARMv7 static audit

`tools/stage24260_trajectory_system_contract.py` produces `stage24.26.0-trajectory-native-contract.txt` and correlates:

- existing `recon/LuaBindings_80.tsv` registrations;
- exported/demangled ARMv7 `GameLua` trajectory methods and related trajectory symbols;
- bounded disassembly of recovered direct/related method bodies;
- exact original script occurrences of the three calls and trajectory state names;
- trajectory/puff/trail-related strings retained in the original library;
- candidate matches in the original 864x480 image metadata corpus.

Missing exported trajectory symbols are treated as evidence rather than a fatal build condition; script/runtime provenance remains useful even when symbols were stripped.

## Validation

Build/install:

```powershell
powershell -ExecutionPolicy Bypass -File .\build-stage24-live-surface-touch-arm64.ps1
```

Runtime test:

1. Open Level **1-1**.
2. Pull and launch **one Red normally**.
3. Let the bird fly into the wood/ground.
4. Leave the level running for a few seconds after the first impact.
5. Do not complete extra actions just to force trajectory behavior.

`addPuffToTrajectory` remaining at zero in this exact test is **not a failure**. Its ownership is audited statically; a later targeted run can exercise it only if the contract requires one.

Collect:

```powershell
powershell -ExecutionPolicy Bypass -File .\pull-stage24-live-log.ps1
```

Upload `stage24-output\stage24-diagnostics.zip`.

## Files to inspect first

- `stage24.26.0-trajectory-runtime.txt`
- `stage24.26.0-trajectory-lua-contract.txt`
- `stage24.26.0-trajectory-native-contract.txt`

The useful runtime shape should include real calls such as:

```text
[stage24.26.0-trajectory-runtime] ADD ... arg1=... x=... y=... callsite='...' pc=...
```

and a lifecycle boundary such as:

```text
[stage24.26.0-trajectory-summary] reason='before-startNewTrajectory' ...
[stage24.26.0-trajectory-runtime] START ... callsite='...' pc=...
```

The audit must interpret those values together with ARMv7 disassembly and untouched Lua ownership before any visible trajectory implementation is accepted.

## Non-goals / frozen behavior

- Audio stays exactly as Stage 24.25.8 left it.
- No trajectory rendering is introduced.
- No guessed dot interval, lifetime, opacity, sprite, draw order, cap, or clear rule is introduced.
- No `birdTrajectory` state is synthesized.
- No achievement, persistence, analytics, Crystal, or unrelated platform stub is changed in this pass.
