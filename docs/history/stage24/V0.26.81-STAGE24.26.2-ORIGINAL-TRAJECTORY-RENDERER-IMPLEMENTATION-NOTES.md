# v0.26.81 — Stage 24.26.2 Original Trajectory Renderer Implementation

## Why this pass exists

Stage 24.26.0 recovered the producer/storage contract and Stage 24.26.1 recovered the untouched ARMv7 consumer:

- `addToTrajectory(slot,x,y)` and `addPuffToTrajectory(slot,x,y)` select `currentBank + slot - 1`;
- there are two banks of three normal trajectory arrays and two banks of three puff arrays;
- `startNewTrajectory()` flips bank `0 <-> 3` and clears the newly selected three normal + three puff arrays;
- untouched Lua owns normal sampling and only calls native `addToTrajectory` after a previous point is more than 20 world units away;
- `GameLua::drawGame()` walks all six slots in order, drawing each slot's normal array before its puff array;
- normal points cycle three sprite names per point;
- the trajectory layer occurs after native gameplay draw pass 1 and before pass 2.

The remaining unresolved resource at the end of Stage 24.26.1 was the 12-byte string used by the puff draw. The original PIC literal cluster now resolves it exactly as `BIRD_SPECIAL` in `INGAME_BIRDS_1`.

This revision restores the recovered native storage and visible renderer. It does **not** change Box2D, bird damping/sleep, bird removal, camera gating, or level-end timing.

## Restored native storage

The three GameLua bindings are no longer behaviorally headless:

```text
startNewTrajectory()
addToTrajectory(slot, x, y)
addPuffToTrajectory(slot, x, y)
```

ARM64 now keeps:

```text
normal[0..5]
puff[0..5]
currentBank = 0 or 3
```

`addToTrajectory` and `addPuffToTrajectory` preserve the original float-to-slot contract and write to:

```text
index = currentBank + int(slot) - 1
```

Only integral slots `1..3` are accepted by the recovered bridge. Invalid values are logged and are never used as an array index.

`startNewTrajectory()` performs the recovered original lifecycle:

```text
currentBank += 3
if currentBank > 3:
    currentBank = 0
clear normal[currentBank .. currentBank+2]
clear puff[currentBank .. currentBank+2]
```

This preserves the opposite bank while a new bird trajectory is being produced.

## Level-load ownership

Stage 24.26.1's full ARMv7 field-consumer scan also identifies `GameLua::loadLevel(lang::String)` as an owner of the trajectory arrays. Its untouched body clears all six normal arrays and all six puff arrays during level load.

Stage 24.26.2 mirrors that ownership at the existing ARM64 `l_loadLevel` boundary. The current bank selector is deliberately **preserved**, matching the observed ARMv7 loadLevel body; only the twelve arrays are cleared.

Runtime tag:

```text
[stage24.26.2-trajectory-native] LEVEL_CLEAR ... bankPreserved=yes
```

This prevents stale trails surviving Restart or a level transition.

## Restored renderer

The trajectory renderer is inserted at the recovered native boundary:

```text
native draw pass 0
native draw pass 1
TRAJECTORY LAYER
native draw pass 2
native draw pass 3
Particles::draw boundary
```

It walks slots `0..5`. Within each slot:

1. draw every normal point;
2. draw every puff point.

Normal point sprite selection repeats per slot:

```text
point 0 -> TRAIL_WHITE_1
point 1 -> TRAIL_WHITE_2
point 2 -> TRAIL_WHITE_3
point 3 -> TRAIL_WHITE_1
...
```

Puff points use:

```text
BIRD_SPECIAL
```

All resources are drawn from `INGAME_BIRDS_1`.

The stored `x/y` values are already original world-pixel coordinates. ARM64 applies the same camera mapping used by the recovered gameplay scene:

```text
screen = (worldPixel - topLeft) * worldScale
```

The untouched trajectory calls pass the same raw Anchor pair `{4,3}` seen on the original native gameplay sprite draw path. The implementation therefore preserves the retained SPRT `pivotX/pivotY` rather than inventing a geometric-centre offset.

No trajectory-specific fade, lifetime, scale multiplier, rotation, or alpha modulation was found in the recovered normal/puff loop, so none is synthesized here.
