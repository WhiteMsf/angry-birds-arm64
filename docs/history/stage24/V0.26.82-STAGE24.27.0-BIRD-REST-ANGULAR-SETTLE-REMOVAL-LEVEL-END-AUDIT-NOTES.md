# v0.26.82 — Stage 24.27.0 Bird Rest / Angular Settle / Removal / Level-End Contract Audit

## Why this pass exists

A live 1-1 run showed a Red remaining as `flyingBird` for more than 13 seconds after launch while the next bird was already available. Visually, some grounded Reds can appear almost settled yet keep rotating very slowly, delaying normal bird cleanup and potentially the level-ending flow.

This revision does **not** assume that behavior is wrong. It audits the complete ownership chain before any change:

- Box2D linear/angular motion;
- awake/sleep state;
- persistent contacts and contact partners;
- untouched Lua `isReadyForRemoveTimer` and the `speed < 0.05` removal gate;
- `flyingBird` / `currentBirdName` / next-bird coexistence;
- camera target ownership;
- `hasMovingObjects` and `hasMovingObjectsZeroTolerance`;
- level-complete / level-failed timers and goal state.

No damping, restitution, velocity, sleep, contact, Lua timer, camera, or terminal behavior is modified.

## Effective physics carried forward

Stage 24.22.8 already restored the ARMv7-proven Box2D tolerances used by this build:

- `b2_linearSlop = 0.05f`;
- `b2_polygonRadius = 0.10f`;
- `b2_timeToSleep = 0.25f`;
- `b2_linearSleepTolerance = 0.10f`;
- `b2_angularSleepTolerance = 0.034906588 rad/s` (2 degrees/s);
- `b2_velocityThreshold = 1.0f`.

The untouched Lua removal threshold remains `vLength(xVel,yVel) < 0.05`.

Stage 24.27.0 explicitly does **not** "fix" a slow Red by increasing damping, forcing `SetAwake(false)`, clamping angular velocity, changing restitution, or changing the Lua threshold.

## Fine-grained runtime observer

New runtime tag:

`[stage24.27.0-bird-rest]`

The observer runs after the untouched Lua `update()` and samples shot birds approximately every six render frames (~10 Hz at 60 Hz), plus immediately whenever one of these changes:

- Box2D awake state;
- number of touching contacts;
- crossing the Lua `speed < 0.05` removal threshold;
- remove-timer type / sign transition.

Each sample records:

- Lua x/y velocity and magnitude;
- Box2D x/y velocity and magnitude;
- body angle, per-frame angle delta and angular velocity;
- `IsAwake()` plus Lua `sleeping`;
- total/touching contacts and contact partner names;
- elapsed observed lifetime and first observed contact frame;
- consecutive observed time below Lua remove speed;
- consecutive observed time below the recovered linear and angular sleep tolerances;
- `isReadyForRemoveTimer` type/value;
- a local diagnostic classification of the immediate Lua remove prerequisites;
- `flyingBird`, current staged bird, bird-ready/fired state;
- camera target and whether it is the audited bird;
- moving-object gates;
- level complete/failed timers and goal count.

When a previously observed shot bird disappears from the `birds` table, a `LIFECYCLE_END` line records its measured lifetime and the simultaneous terminal/camera state.

The observer never calls `removeBird`, never calls `SetAwake`, and never writes any field it reports.

## Interpretation rule

Do not change physics merely because a Red lives "too long" by eye.

The next implementation decision must name the actual owner visible in this audit. Examples:

- persistent touching contact repeatedly re-awakens the body;
- angular velocity remains above the ARMv7 sleep tolerance;
- Box2D sleeps correctly but Lua linear speed never keeps the remove timer alive;
- the bird passes the local removal prerequisites but camera or another Lua branch retains ownership;
- bird cleanup is normal and only the level-end moving-object gate is delaying completion;
- the ARM64 behavior matches the recovered ARMv7 contract and is therefore a vanilla quirk.
