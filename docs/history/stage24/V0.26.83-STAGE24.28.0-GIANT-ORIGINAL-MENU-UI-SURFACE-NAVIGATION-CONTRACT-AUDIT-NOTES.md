# v0.26.83 — Stage 24.28.0 — Giant Original Menu/UI Surface & Navigation Contract Audit

## Scope

Stage 24.28.0 is diagnostic-only. It begins the menu/UI completion block after the audio, trajectory, and bird-settle investigations without implementing any new screen, navigation shortcut, save format, platform service, or cutscene behavior.

The audit intentionally spans the complete known vanilla UI frontier rather than auditing one button at a time:

- startup/main menu;
- episode selection;
- level selection and its complete original item table;
- gameplay HUD handoff;
- pause;
- level complete / level failed;
- Replay / Next / Home / Back-style transitions;
- settings/options;
- credits/about where present in the 1.4.2 corpus;
- tutorials/popups;
- Golden Egg / special progression surfaces;
- achievement/leaderboard/platform entry points;
- Crystal/Game Center/advertisement compatibility boundaries;
- persistence-facing callbacks such as `saveLuaFile`;
- video/cutscene entry points.

## Important deferred gate: first Level 1 film

The first level of the first campaign has a pre-level film/cutscene in the original game. Stage 24.28.0 treats that as an explicit required future gate.

This revision DOES audit:

- `playVideo` / `releaseCutScenes` native ownership;
- script/level references to video/cutscene/story/intro concepts;
- relevant Lua closure constants and menu callbacks;
- the untouched ARMv7 native platform surface.

This revision DOES NOT attempt to play, fake, skip, or replace the film.

## Runtime inventory

Immediately after the preserved untouched `initializeMenu()` returns, and before the Stage24 harness forces the direct Level1 gameplay path, the runtime dumps:

- every relevant global Lua closure and relevant nested child Proto;
- string constants from those Protos, including callback/destination names;
- relevant global tables;
- every global table owning an `items` table;
- nested page/item scalar fields to bounded depth;
- `settings`, `highscores`, level-selection page tables, terminal pages and platform/frontier globals.

This is read-only. No menu callback is executed by the inventory.

## Live navigation observer

The frame loop records changes to:

- `currentGameMode`;
- `currentMenuPage`;
- `oldMenuPage`;
- `newMenuPage`;
- `popupPage`;
- `newPopupPage`;
- `loadLevelDelayed`;
- current level;
- completion/failure timers;
- ad/video/Game Center/Crystal-facing flags.

No transition is synthesized.

## Test

Build normally:

```powershell
powershell -ExecutionPolicy Bypass -File .\build-stage24-live-surface-touch-arm64.ps1
```

A useful broad run is:

1. let Level 1-1 boot;
2. open Pause at least once;
3. return to gameplay;
4. complete OR fail the level;
5. click any terminal-menu controls that are currently reachable (Replay / Next / Home / Back as available).

It is not necessary to reach every original screen. The post-`initializeMenu()` inventory exists specifically to capture pages that the current direct-Level1 harness cannot yet navigate to.

Then:

```powershell
powershell -ExecutionPolicy Bypass -File .\pull-stage24-live-log.ps1
```

Upload `stage24-diagnostics.zip`.
