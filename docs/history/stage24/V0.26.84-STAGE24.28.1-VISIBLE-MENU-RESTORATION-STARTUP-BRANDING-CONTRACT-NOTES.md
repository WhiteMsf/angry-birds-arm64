# v0.26.84 — Stage 24.28.1

## Visible Menu Surface Restoration + Startup Branding Contract Audit

This revision follows the Stage 24.28.0 giant menu/UI inventory.

### Behavior change

The live GLES menu bridge no longer restricts the untouched `drawMenu()` closure
to only `pause`, `levelComplete`, and `levelFailed`.

Whenever original Lua owns:

- `currentGameMode == updateMenu`, and
- `currentMenuPage` names a concrete page,

the renderer now passes that exact page/state to the same untouched original
`drawMenu()` closure already proven by the pause and terminal-menu stages.

No page contents, callbacks, hitboxes, navigation targets, or selection state are
manufactured by native code.

The immediate target is the vanilla chain already observed in 24.28.0:

`levelComplete -> buttonMenu -> levelSelectionPagesBasic -> episode/main navigation`

The `title_theme` audio behavior remains owned by untouched `prepareMenuPage()`.

### Startup branding

The user correctly noted that the retail game boots through branding/splash
screens before the menus. Stage 24.28.0 found these original Lua symbols:

- `createStartUpAssets`
- `updateSplashes`
- `SPLASH_CLICKGAMER`
- `SPLASH_ROVIO`
- `SPLASH_ANGRY_BIRDS`
- `SPLASH_LOADING`
- `LITE_SPLASH`
- `TEXT_SPLASH_LOADING_SPRITE`

Stage 24.28.1 deliberately does **not** display these yet. It adds two audits:

1. a full untouched Lua Proto/instruction dump for startup/splash owners;
2. build-time provenance from the original `gamelogic.lua`, image DATs, and
   localization corpus.

This avoids inventing splash order, duration, edition-dependent Clickgamer
behavior, or loading-page semantics from filenames.

### Explicitly unchanged

- Stage24 still boots directly to Level1 for this harness revision.
- The Level1 first-entry story/cutscene remains unimplemented.
- Persistence remains a stub boundary.
- No physics, bird settling, score, audio, trajectory, camera, or level-end
  behavior is changed.

### Pass criteria

This stage is a restoration/frontier pass, not final menu closure.

PASS means the untouched menu state machine can render at least the reached
Main/Episode/Level-selection surfaces through the generalized renderer without
regressing gameplay, and any remaining missing primitive/asset is identified
concretely in logs rather than hidden by the old three-page allow-list.
