# v0.26.87 — Stage 24.28.4
## Overlay Render Ownership + Platform Button Boundary Audit

Observed v0.26.86 regression/fault:

1. `levelComplete`/`pause`/`levelFailed` were treated like standalone root menus, so Stage24 cleared the viewport before `drawMenu()`. Their untouched Lua pages only draw a translucent shade/UI and therefore produced black underneath instead of the final gameplay scene.
2. Main-menu trailer input reached untouched `gotoAngryBirdsTrailer()`, which called missing global `openURL()` and faulted Lua.
3. The Stage24.27.0 bird-rest telemetry remains enabled because the same run strongly reproduced the slow-settling Red.

This build separates original `updateMenu` pages into two renderer ownership classes:

- `GAMEPLAY_OVERLAY`: `pause`, `levelComplete`, `levelFailed`, and the four recovered `gameFinished*` variants. Stage24 redraws the gameplay frame first, then executes untouched `drawMenu()` over it. Existing reconstructed `drawGame` HUD gates still decide whether score/floating-score/MENU_BUTTON appear.
- `FULL_FRAME_MENU`: every other concrete `updateMenu` page. These keep Stage24.28.3 ownership: gameplay world/HUD are skipped and untouched `drawMenu()` owns theme background/foreground/page rendering.

`openURL` is now a diagnostic compatibility boundary. It logs exact arguments, caller/page/mode and returns no Lua values. It deliberately does **not** launch Android `ACTION_VIEW`, a browser, store or social app in this stage. Static and runtime audits inventory the original producers before a final platform implementation decision.

No physics constants, bird damping/sleep thresholds, audio behavior, persistence, startup splashes, or Level1 first-entry story/cutscene are changed.
