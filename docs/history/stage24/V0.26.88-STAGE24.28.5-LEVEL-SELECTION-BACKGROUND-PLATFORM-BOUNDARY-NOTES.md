# v0.26.88 — Stage 24.28.5
## Level Selection Background Fidelity + Platform Boundary Fix

The v0.26.87 runtime isolated two exact contract mismatches.

1. `levelSelectionPagesBasic` rendered its original `LS_BACKGROUND` art, but transparent/partially transparent pixels exposed a forced black full-frame clear. Untouched `updateMenu()` already owns the required base color: it reads `currentMenuPage.bgColor.red/green/blue` and calls `setBGColor(...)`. For the observed first Poached Eggs page the original table is RGB `(41,118,142)`. Stage24 had left `setBGColor` as a no-op.
2. Untouched trailer/store/social callbacks do **not** call a global `openURL`. Their Lua 5.1 bytecode resolves `_G -> res -> openURL -> CALL`. v0.26.87 installed only a global compatibility function, so `res.openURL` remained nil and the trailer callback was still Lua-fatal.

This version restores both proven contracts without inventing behavior:

- `setBGColor(r,g,b)` records the exact page-owned RGB supplied by untouched Lua. Full-frame menu clears use that color before page-specific translucent art is drawn. Existing theme-owned `drawBackgroundNative()` still performs its own proven theme clear where applicable.
- the existing diagnostic `openURL` no-launch handler is installed at `_G.res.openURL`. It logs the requested URL/caller/page but deliberately launches no browser/Intent yet.
- a new runtime/bytecode audit correlates the page table `bgColor`, `setBGColor` call, resulting frame clear, `drawLevelSelectionBackground`, and `_G.res.openURL` lookup.

No physics constants, bird settling behavior, audio, persistence, startup splashes, or the Level1 first-entry story/cutscene are changed.
