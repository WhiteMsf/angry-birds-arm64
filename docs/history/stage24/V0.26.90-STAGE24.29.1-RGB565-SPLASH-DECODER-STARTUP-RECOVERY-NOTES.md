# v0.26.90 — Stage 24.29.1: RGB565 Splash Decoder / Startup Recovery

The first real Stage24.29.0 startup run failed deterministically on frame 1 while drawing `SPLASH_ROVIO`.

The runtime log proved that the retained original `SPLASHES_SHEET_1.pvr` and `SPLASHES_SHEET_2.pvr` use legacy PVR v2 pixel type `0x13` (`GL_RGB_565`), 16 bpp, masks `F800/07E0/001F/0000`. The payload sizes exactly equal `width * height * 2` for the stored levels. The old runtime accepted only the already-proven RGBA4444 (`0x10`) and ETC1 (`0x36`) contracts, so both splash atlases were intentionally rejected before upload and the boot renderer failed on its first frame.

Stage24.29.1 extends that same fail-closed PVR v2 parser with the exact RGB565 contract already named by the original Stage23.1 format table. No pixels are converted or recreated: the user's original PVR payload remains byte-identical in the locally built APK and GLES uploads it as `GL_RGB` + `GL_UNSIGNED_SHORT_5_6_5` using the existing allocate + subimage route.

The same exact PVR v2 RGB565 contract had also been responsible for the long-standing non-fatal warnings for `BACKGROUNDS_GE_1.pvr` and `BACKGROUNDS_MAIN_1.pvr`; those atlases become decodable through the same generic fix when present. This stage does not otherwise change menu ownership, physics, audio, persistence, platform services, cutscenes, or startup timing.

Build-time audit `stage24.29.1-rgb565-splash-contract.txt` requires both splash sheets to match the exact proven header/mask/payload contract before the APK is built.

Runtime success criteria:

- `SPLASHES_SHEET_1.pvr` and `SPLASHES_SHEET_2.pvr` log `format=RGB565-v2 exact=yes`.
- GPU upload logs `format=RGB565` with no GL error.
- Stage24.29.0 boot logs `DISPLAY ... SPLASH_ROVIO` instead of `splash draw failed` / `render FAIL frame=1`.
- Branding advances to Angry Birds and then the untouched Main Menu without exposing the hidden Level1 scaffold.

`SPLASH_CLICKGAMER` and `SPLASH_LOADING` retain the Stage24.29.0 policy: no missing art is fabricated when the audited corpus has no concrete owner.
