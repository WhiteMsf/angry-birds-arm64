# v0.26.91 — Stage 24.30.0 — Original Cutscene / Story System Contract Audit

## Why this stage exists

v0.26.90 restored the vanilla startup path and, for the first time, reached Poached Eggs 1-1 through the real menu tree. The untouched first-entry path then entered `loadCutScenes()` and failed in `loadImages()` because `_G.res.createSpriteSheet` was absent.

This stage is deliberately **diagnostic-only** for the story system. It does not implement a cutscene renderer and does not claim that any sprite sheet is loaded.

## Runtime probes

- installs `_G.res.createSpriteSheet(...)` as a void audit probe;
- records every argument, Lua caller/source, stripped Proto/PC and active menu/story state;
- replaces the historical `releaseCutScenes` no-op with an observable void audit probe;
- dumps untouched Lua Proto trees for `loadImages`, `loadCutScenes`, `prepareCutScene`, `releaseCutScenes`, `getCutsceneBackgroundWidth`, `prepareMenuPage`, `setActiveMenuPageDelayed`, `updateMenu`, and `loadLevelFromMenu`;
- dumps the original `theme1Start` and `introAnimation` tables after `initializeMenu()`.

The `createSpriteSheet` probe intentionally does **not** mutate SpriteDB, resource ownership, textures, or rendering. Its purpose is to let original Lua advance until the next real native dependency.

## Static ARMv7 / corpus audit

`tools/stage24300_cutscene_story_contract.py` inventories:

- script provenance for cutscene/story producers;
- every `CUTSCENES*.dat` metadata container and its texture/story/cutscene names;
- ARMv7 symbols and targeted disassembly for `createSpriteSheet` / `releaseSpriteSheet` related methods;
- cutscene/story strings in the original ARMv7 library;
- source guards proving this package remains audit-only.
