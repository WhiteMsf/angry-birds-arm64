# v0.26.92 — Stage 24.30.1 — Dynamic Cutscene SpriteSheet + Render-State Closure

## Why this stage exists

v0.26.91 proved that first entry into Poached Eggs 1-1 reaches the untouched `gameStart` story through `loadCutScenes() -> loadImages({"CUTSCENES"})`. The original Lua requests six dynamic cutscene DATs through `_G.res.createSpriteSheet(path [, force])`. The Stage24.30.0 audit probe deliberately did not mutate the resource registry, so `STORY_BEGIN_*` remained unavailable. The same run also exposed the first live four-argument `setRenderState(x,y,sx,sy)` call, while the ARM64 bridge incorrectly accepted only five or seven arguments.

This stage restores those two proven native contracts only. It does **not** hand-author the first-level story or its animation.

## Dynamic sprite-sheet ownership

`_G.res.createSpriteSheet(path [, force])` now:

- accepts the ARMv7-proven string path plus optional boolean `force`;
- returns zero Lua values;
- loads the requested original DAT into the same `SpriteDB`/global sprite registry used by `drawSprite`, `getSpriteBounds`, and other resource calls;
- acquires the exact original texture payload(s) named by that DAT only when the dynamic sheet is created;
- reuses an already-created dynamic sheet when `force=false`;
- unloads and recreates the bridge-owned dynamic sheet when `force=true`;
- rolls back registry/texture ownership if a required texture cannot be decoded/uploaded.

`_G.res.releaseSpriteSheet(path)` removes only sheets loaded through this dynamic bridge, restores any retained global owner for colliding sprite names, decrements texture references, and deletes the GLES texture when its last dynamic owner is released. Static bootstrap sheets are never removed by this bridge.

The untouched Lua `releaseCutScenes` closure is preserved and verified at startup instead of being replaced by the historical headless no-op.

## Original first-entry assets

The build fail-closes on the six sheets proven by Stage24.30.0:

- `CUTSCENES_BACKGROUNDS_1.dat`
- `CUTSCENES_BACKGROUNDS_2.dat`
- `CUTSCENES_BACKGROUNDS_3.dat`
- `CUTSCENES_BACKGROUNDS_4.dat`
- `CUTSCENES_ELEMENTS_1.dat`
- `CUTSCENES_ELEMENTS_2.dat`

Their DATs and texture payloads are copied only from the user's untouched original asset tree during the local build. They remain outside the bootstrap registry and are materialized into app-private storage, but become visible to SpriteDB/GLES only when original Lua invokes `createSpriteSheet`.

PVR v2 texture bytes remain byte-identical. The existing exact decoder supports the recovered RGBA4444, RGB565, and ETC1 contracts; PNG, if named by a proven DAT, uses the existing lossless RGBA8 build transport. No Rovio pixel/audio payload is redistributed in this source package.

## Progressive `setRenderState`

The ARM64 bridge now mirrors the recovered progressive ARMv7 arities:

- `setRenderState(x, y)` — translation;
- `setRenderState(x, y, sx, sy)` — translation + scale;
- `setRenderState(x, y, sx, sy, angle)` — plus rotation;
- `setRenderState(x, y, sx, sy, angle, px, py)` — plus pivot.

Missing later components retain identity/default values (`scale=1`, `angle=0`, `pivot=0`). The live `gameStart` story is expected to exercise the four-argument form that crashed v0.26.91.

## Test

Fresh launch, then:

`Rovio -> Angry Birds -> Main Menu -> Play -> Poached Eggs -> Level 1-1`

After tapping Level 1, do not immediately skip or repeatedly tap. Let the first-entry story run for several seconds. This revision intentionally leaves all story sequencing, scrolling, timers, sounds, and the eventual `gotoFirstLevel` handoff under untouched Lua ownership.

A visible `STORY_BEGIN_*` sequence is possible if no further native boundary remains. If the story stops at a new missing native/resource contract, collect diagnostics rather than patching around it.
