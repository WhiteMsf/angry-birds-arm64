# v0.26.93 — Stage 24.30.2 Pre-GPU Dynamic-Sheet Bootstrap Hotfix

## Runtime finding from v0.26.92

The v0.26.92 dynamic `res.createSpriteSheet` bridge was bound before the Stage24 GLES renderer is constructed. During the pre-loader Level1 scaffold, untouched `releaseCutScenes() -> loadImages()` re-requests already-bootstrap-resident MENU/OTHER image sheets with `force=false`. The recovered original contract permits immediate reuse of an existing sheet, but the ARM64 bridge rejected every call up front when `gStage24301GpuRenderer == nullptr`, aborting Lua before the startup splashes and producing a black screen.

## Fix

- Require only the shared `SpriteDB` for `force=false` reuse of a sheet that is already resident.
- Defer the GLES renderer requirement until a call actually needs dynamic texture upload/recreation.
- Keep fail-closed behavior if a genuinely dynamic/non-resident sheet is requested before the GPU bridge exists.
- Preserve Stage24.30.1 dynamic CUTSCENES ownership, texture reference counting, release behavior, and progressive `setRenderState` semantics unchanged.

Expected pre-GPU evidence:

`[stage24.30.2-pre-gpu-reuse] ... action=REUSE_PRELOADED gpuReady=no`

Expected post-startup first-entry path remains:

`loadCutScenes -> res.createSpriteSheet(CUTSCENES_*) -> dynamic registry/GLES LOAD -> gameStart`.
