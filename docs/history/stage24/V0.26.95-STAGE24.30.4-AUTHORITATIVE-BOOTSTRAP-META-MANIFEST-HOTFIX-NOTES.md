# v0.26.95 — Stage 24.30.4: Authoritative Bootstrap Meta Manifest Hotfix

## Why v0.26.94 was still black
The v0.26.94 build correctly discovered, staged, and packaged supplemental MENU/OTHER sheets such as `GOLDEN_EGGS_SHEET_2.dat`. The runtime, however, still contained two historical hardcoded C++ lists: one controlling which sprite metadata DATs were extracted from the APK, and a second controlling which DATs were loaded into the bootstrap `SpriteDB`. Consequently the new DAT and texture were physically present in the APK, but `gSprites->hasSheet("GOLDEN_EGGS_SHEET_2")` remained false before GLES creation, so untouched `createSpriteSheet(..., false)` again failed closed as a supposedly dynamic request.

## Stage 24.30.4 closure
The PowerShell build now writes one ordered `sprite-meta/bootstrap-menu-meta.txt` from the exact concrete `$menuMetaNames` set for this edition. The ARM64 runtime consumes that same manifest twice: first to extract every DAT from APK assets into app-private storage, then to load every entry into the global `SpriteDB` in the same order. There is no second C++ sheet-name inventory to drift.

`CUTSCENES_*` remain outside this manifest and remain genuinely dynamic.

## Expected evidence
Before GLES exists, the log should show:

```text
[stage24.30.4-bootstrap-meta] EXTRACT ... name='GOLDEN_EGGS_SHEET_2.dat' action=PASS
[stage24.30.4-bootstrap-meta] LOAD ... name='GOLDEN_EGGS_SHEET_2.dat' action=SPRITEDB_RESIDENT
[stage24.30.2-pre-gpu-reuse] ... key='GOLDEN_EGGS_SHEET_2' ... action=REUSE_PRELOADED gpuReady=no
```

No `dynamic GPU bridge unavailable` is expected during startup.
