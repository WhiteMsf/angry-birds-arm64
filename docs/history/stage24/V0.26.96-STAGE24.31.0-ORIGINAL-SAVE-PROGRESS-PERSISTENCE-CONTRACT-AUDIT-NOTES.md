# v0.26.96 — Stage 24.31.0: Original Save / Progress Persistence Contract Audit

## Why this stage starts with an audit
The vanilla boot/menu/story path is now closed through the first-entry 1-1 cutscene and gameplay handoff. That finally gives the original Lua enough surface to exercise persistence naturally: level completion mutates `highscores`, menu/settings callbacks mutate `settings`, Golden Egg paths touch both roots, and the untouched `saveLuaFileWrapper` calls the native `saveLuaFile` boundary.

This revision intentionally does **not** write any profile files. The existing Stage24 no-write behavior is preserved while the exact contract is recorded.

## Runtime probes
The blanket stubs for these four boundaries are replaced by observational equivalents:

- `saveLuaFile`
- `checkForLuaFile`
- `createDirectory`
- `saveLevel`

They preserve the historical no-return/no-write Stage24 behavior. `saveLuaFile` logs all three Lua arguments, caller/Proto/PC, current menu/level context, and snapshots the global table named by argument 2 when it is a string.

The ARMv7 symbol already establishes the native shape as:

```text
GameLua::saveLuaFile(lang::String, lang::String, bool)
```

The runtime audit is meant to prove what those two strings and the boolean mean at every real callsite before any serializer is implemented.

## ARMv7 static audit
`tools/stage24310_persistence_contract.py` inventories and disassembles the original ARMv7 persistence functions, including the available:

```text
GameLua::saveLuaFile(...)
GameLua::loadLuaFile(...)
GameLua::checkForLuaFile(...)
GameLua::createDirectory(...)

```

The audit also scans the original Lua corpus for filenames and callsite strings. No disk format is inferred from filenames alone.
