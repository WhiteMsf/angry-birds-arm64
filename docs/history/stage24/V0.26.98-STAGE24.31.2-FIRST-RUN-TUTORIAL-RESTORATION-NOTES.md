# v0.26.98 — Stage 24.31.2 — First-run / Tutorial Restoration

This stage removes the oldest remaining gameplay bootstrap bypass: v0.9.3's unconditional `birdTutorialPopups = {}`.

Recovered original behavior:
- `loadLevelInternal()` sees a bird definition's `tutorialInfo` and, when `settings.tutorials[sprite]` has no retained table, creates that table, stores the tutorial info, and queues it in `birdTutorialPopups`.
- For Red on 1-1 the persisted marker is `settings.tutorials.BIRD_RED.sprite = "TUTORIAL_1"`.
- `updateGame()` pauses physics while the queue is non-empty and owns the `TUTORIAL_OK` hit test/removal.
- `drawGame()` draws a 50% black shade, the tutorial background box, a KA3D COMP composite (`res.drawCompoSprite`), then `TUTORIAL_OK`.

Stage24 now retains all COMP child entries from `TUTORIALS_composprites.dat`, implements the four-argument `res.drawCompoSprite` visual boundary, and replays only the proven tutorial tail over the already-restored native gameplay renderer while original `updateGame()` remains the input/state owner.

Persistence remains Stage24.31.1. The original level loader creates the retained `settings.tutorials.BIRD_RED` marker; once settings are saved (for example by completing 1-1), a fresh process reloads it and the tutorial is suppressed on subsequent entry.

For an existing Stage24 profile that already contains the Red marker from earlier bypassed runs, use `reset-stage24-tutorial-first-run.ps1`. It removes only app-private `settings.lua`; `highscores.lua` is left untouched.
