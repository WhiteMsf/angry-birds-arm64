# v0.26.98a — Stage 24.31.2a — Hidden Bootstrap Tutorial Rollback Hotfix

## Runtime finding from v0.26.98

The restored vanilla tutorial gate worked, but Stage24's legacy hidden Level1 bootstrap also executed `loadLevelInternal()` before the user entered gameplay. On a clean settings profile that hidden load:

- queued `TUTORIAL_1` in `birdTutorialPopups`;
- wrote `settings.tutorials.BIRD_RED.sprite = "TUTORIAL_1"` in memory;
- allowed the tutorial overlay to flash during menu navigation;
- caused the later real post-cutscene Level1 load to see BIRD_RED as already registered and therefore produce no tutorial queue.

The diagnostic proof was `POST_LOAD queue=1`, a successful `DRAW_COMPO TUTORIAL_RED`, then the queue disappearing at the real `updateLoading` transition.

## Fix

Before the Stage24-only hidden bootstrap `loadLevelInternal()` call, snapshot only the tutorial-owned state:

- `settings.tutorials`
- `birdTutorialPopups`

Immediately after that hidden load returns, restore the snapshot. All other world/camera/bootstrap state remains untouched.

The real menu -> gameStart cutscene -> `updateLoading` path is not intercepted. It is now the first load allowed to create the Red tutorial queue and seen-state mutation.

## New runtime markers

- `BOOTSTRAP_CAPTURE ... action=SNAPSHOT_BEFORE_HIDDEN_LEVEL`
- `BOOTSTRAP_SUPPRESS ... action=ROLLBACK_HIDDEN_LEVEL_ONLY`
- `POST_LOAD ... action=POST_BOOTSTRAP_ROLLBACK_STATE`

Expected clean first-run sequence:

1. hidden bootstrap may temporarily produce `TUTORIAL_1` internally;
2. 24.31.2a restores queue=0 / no BIRD_RED seen entry;
3. Main Menu and cutscene run with no tutorial overlay leak;
4. real Level1 `updateLoading` changes queue 0 -> 1;
5. tutorial remains visible with physics paused until `TUTORIAL_OK` is clicked;
6. settings persistence then records the seen tutorial so a restarted second entry does not show it again.
