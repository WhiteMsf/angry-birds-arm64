# v0.4.1

This revision addresses the Android abort:

`FORTIFY: strchr: prevented read past end of buffer`

Lua 5.1 stores string payload bytes in tail-allocated memory immediately after
the `TString` header. Its GC checks weak-table mode using
`strchr(svalue(mode), 'k'/'v')`. Modern Android/Bionic FORTIFY can infer an
incorrect fixed object bound for that macro-derived pointer and abort.

The patch keeps FORTIFY enabled globally. It does **not** disable Android's
safety checks. Instead it replaces only those two GC searches with a tiny
noinline scanner that preserves `strchr` semantics for Lua's guaranteed
NUL-terminated TString payload.

Stage 3 output is also unbuffered and now prints checkpoints before each
runtime initialization step, so any future abort identifies its exact phase.
