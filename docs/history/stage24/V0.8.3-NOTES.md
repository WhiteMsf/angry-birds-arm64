# v0.8.3 — Stage 7 bird-state verifier fix

v0.8.2 proved something more interesting than the assertion expected.

After the original `loadLevelInternal()` returned:

- total body types were `16 dynamic / 5 static`
- Stage 6's manual materializer had `18 dynamic / 3 static`
- the first prefix-matched bird (`RedBird_2`) had mass `0`

That is not broken physics. In Box2D 2.1.2, changing a body to
`b2_staticBody` resets its dynamic mass to zero. The original loader's bird
queue logic changes **two of the three RedBird bodies to static**, leaving one
active bird dynamic.

The old verifier simply selected the alphabetically first `RedBird_` body and
then incorrectly expected dynamic-bird mass.

v0.8.3 now:

- identifies the active RedBird by `b2_dynamicBody` type;
- logs all three RedBird names/types/masses/positions;
- verifies exactly `1 dynamic + 2 static` RedBirds;
- checks the original circle mass only on the active dynamic bird.

No loader or physics behavior changed. The zero-mass queued bird from v0.8.2 is
now treated as evidence that the original `getNextBird` / body-type path ran.
