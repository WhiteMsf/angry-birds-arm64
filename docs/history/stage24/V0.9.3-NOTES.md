# v0.9.3 — escape the original tutorial UI gate

v0.9.2 was a major partial success: **all 120 calls to the original
`update(dt, frameTime)` returned normally**.

The semantic verifier failed because the level never entered active gameplay:

- `time` advanced to ~2.0 s
- `currentFrame` advanced to 120
- `gameTimer` stayed 0
- `levelStartTimer` stayed 0.01
- Box2D stayed disabled
- the pig never moved

Static bytecode inspection of the original 3,955-instruction `updateGame()`
found the cause near PCs 325-470.

The function begins a tutorial-popup gate:

- it checks `#birdTutorialPopups`
- while a first-run tutorial popup is pending it calls
  `setPhysicsEnabled(false)`
- it executes the headless draw/pause-page path
- then returns **before** the later block that advances `levelStartTimer`,
  enables physics, and increments `gameTimer`

The original full app would render and dismiss that popup through UI/input.
The headless harness cannot.

v0.9.3 therefore clears only the UI-only `birdTutorialPopups` queue after the
original level loader returns. It logs the queue size before and after.

The original `update()`, `updateGame()`, level-start timer logic, bird logic,
physics-enable call, game timer, Box2D bridge, and Level1 remain untouched.

Expected next evidence:

- `levelStartTimer` begins advancing after frame 1
- original `updateGame()` enables Box2D at roughly the one-second mark
- `gameTimer` advances
- Level1 bodies begin moving under real Box2D during the original frame loop
