# v0.9.4 — keep the pause-page animation in HIDDEN state

v0.9.3 successfully escaped the first-run tutorial gate:

- tutorial queue was `before=1`, `after=0`;
- frame 1 completed;
- `time = 1/60`;
- `currentFrame = 1`;
- `gameTimer = 1/60`;
- `levelStartTimer` advanced from `0.01` to `0.026667`.

Frame 2 then failed after a `setRenderState` call with:

`attempt to get length of field 'items' (a nil value)`

Static bytecode inspection found the exact path at the end of the original
3,955-instruction `updateGame()`:

```text
if elementAnimations.ingamePausePageScroll.state ~= "HIDDEN"
   and #birdTutorialPopups == 0 then
    ...
    drawMenuPage(pausePage)
end
```

`drawMenuPage()` calls original `drawMenuItems(page)`, which evaluates
`#page.items`. Our headless `pausePage` deliberately has no rendered menu item
tree, so the error is expected.

The real application keeps the pause-page animation in `HIDDEN` state during
normal gameplay. Our previous scaffold supplied only `percentage=100`, leaving
`state=nil`; that accidentally entered the rendering path every frame.

v0.9.4 sets:

`elementAnimations.ingamePausePageScroll.state = "HIDDEN"`

before the frame loop. This does not replace or bypass gameplay logic; it
restores the normal non-paused UI state so the original updateGame skips the
pause-menu drawing branch.

Static inspection also confirms the original level-start sequence:

- while `levelStartTimer < 1.0`, it adds `dt`;
- once the timer reaches ~1 second, original `updateGame()` calls
  `setPhysicsEnabled(true)` and sets `levelStartTimer = 10`.

So if no new dependency appears first, real Box2D should be enabled around
frame 60.
