# v0.9.5 — exact stripped-Lua VM failure locator

v0.9.4 reached the most important transition yet:

- frames 1..60 of original `update()` completed;
- `gameTimer` reached 1.0;
- `levelStartTimer` reached 1.01;
- on frame 61 the **original `updateGame()` called `setPhysicsEnabled(true)`**.

Immediately afterward, still inside the same original Lua frame, a stripped
bytecode access failed with:

`attempt to index field '?' (a nil value)`

Because the Lua chunks have no line tables or local-variable debug info, the
normal error text cannot identify the instruction.

v0.9.5 adds a diagnostic-only VM hook for frames >= 58. It uses Lua 5.1's
private VM state (`lua_State::savedpc` + current Lua `Proto`) to report:

- the exact original global Lua function;
- the exact instruction PC inside that stripped function;
- a call-stack summary.

No gameplay state, Lua control flow, Box2D behavior, loader behavior, or
headless UI state is changed.

This is deliberately a diagnostic pass: the next log should identify the exact
nil access rather than guessing which of the thousands of `updateGame()`
instructions caused it.
